`POST /v1/images/generations`

Endpoint text-to-image использует тело запроса `application/json`. Передайте prompt, держите HTTP-запрос открытым и прочитайте готовое изображение из `data[0].b64_json` в том же ответе.

<Note>
  Используйте `{{openai-base-url}}` как `Base URL`. API Key BetterToken передается через `Authorization: Bearer YOUR_API_KEY`.
</Note>

<Tip>
  В Playground справа можно заполнить `Authorization` и тело запроса, а затем отправить запрос напрямую на `{{images-generations-url}}`.
</Tip>

<Warning>
  Не помещайте API keys во frontend-код браузера, Git-репозитории, тикеты, скриншоты или логи. Для server-side proxy calls храните ключи только в переменных окружения сервера или secret manager.
</Warning>

## Выберите нужный сценарий

- **Сгенерировать изображение из текста и сохранить результат:** оставайтесь на этой странице. Начните с примера `curl`, затем используйте раздел **Сохранение изображения** для декодирования `data[0].b64_json`.
- **Изменить исходное изображение:** используйте [Image to image](/api-reference/images-edits), где запрос отправляется как `multipart/form-data` с одним или несколькими файлами.
- **Выбрать модель, параметры и оценить бюджет:** проверьте актуальные Model ID и цены в <a href={"{{model-plaza-url}}"}>model plaza</a>, а параметры запроса — в разделе **Рекомендуемые значения** ниже. Полный контекст первого запроса приведён в [статье о GPT Image 2](https://bettertoken.ai/ru/blog/gpt-image-api-pervyy-zapros/).

## Быстрый старт с curl

Используйте `{{openai-base-url}}` как Base URL и отправьте запрос на `{{images-generations-url}}`:

```bash
curl -X POST "{{images-generations-url}}" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "prompt": "A product photo of a green ceramic mug on a studio table",
    "size": "1024x1024",
    "n": 1,
    "response_format": "b64_json",
    "output_format": "png"
  }'
```

## Рекомендуемые значения

Передавайте эти поля явно в каждом запросе:

```json
{
  "model": "gpt-image-2",
  "n": 1,
  "response_format": "b64_json",
  "output_format": "png"
}
```

| Параметр | Что передавать | Назначение |
| --- | --- | --- |
| `model` | `gpt-image-2` | Выбирает image model. |
| `prompt` | Текстовое описание | Обязательное описание изображения. Укажите объект, стиль, композицию и важные ограничения. |
| `size` | Например, `1024x1024` | Размер и соотношение сторон. |
| `n` | `1` | Количество изображений в одном запросе. Для нескольких изображений отправляйте отдельные запросы. |
| `response_format` | `b64_json` | Возвращает изображение в base64 в `data[0].b64_json`. |
| `output_format` | `png` | Позволяет сохранить результат как PNG. |

Чтобы сгенерировать несколько изображений, отправляйте несколько независимых запросов. Не рассчитывайте на один запрос с `n > 1`.

## Рекомендуемые размеры

| `size` | Соотношение | Сценарий |
| --- | --- | --- |
| `auto` | Auto | Автоматический выбор размера |
| `1024x1024` | `1:1` | Квадратные изображения, аватары, обложки, assets |
| `1536x1024` | `3:2` | Landscape-постеры, баннеры, сцены |
| `1024x1536` | `2:3` | Portrait-обложки для мобильных и постеры |
| `1536x1152` | `4:3` | Стандартные landscape-изображения, product images, content graphics |
| `1152x1536` | `3:4` | Стандартные portrait-изображения, mobile covers, vertical posters |
| `2048x2048` | `1:1` | High-resolution квадратные изображения |
| `2048x1152` | `16:9` | High-resolution landscape-изображения |
| `3840x2160` | `16:9` | 4K landscape-изображения |
| `2160x3840` | `9:16` | 4K portrait-изображения |

`size` задает ожидаемое соотношение сторон и уровень размера. Фактические пиксели в ответе могут быть сопоставлены или скорректированы сервером. Используйте размеры декодированного изображения, а не принудительную обрезку до запрошенного значения.

## Сохранение изображения

Успешный ответ следует OpenAI-совместимой форме image response:

```json
{
  "created": 1710000000,
  "data": [
    {
      "b64_json": "iVBORw0KGgoAAAANSUhEUgAA...(truncated)"
    }
  ]
}
```

Прочитайте `data[0].b64_json` и сохраните его как base64 image content. Ответ может содержать дополнительные поля, например `revised_prompt`; клиент должен разрешать такие поля.

Всегда задавайте `output_format: "png"`. Затем сохраняйте декодированное изображение как `.png` без проверки file headers.

```python
import base64
import json
from pathlib import Path

response = json.loads(Path("response.json").read_text(encoding="utf-8"))
b64_json = response["data"][0]["b64_json"]

if "," in b64_json and "base64" in b64_json.split(",", 1)[0]:
    b64_json = b64_json.split(",", 1)[1]

image_bytes = base64.b64decode(b64_json)
Path("output.png").write_bytes(image_bytes)
```

### Пример JavaScript (Node.js)

```js
import { writeFile } from "node:fs/promises";

const response = await fetch("{{images-generations-url}}", {
  method: "POST",
  headers: {
    Authorization: "Bearer YOUR_API_KEY",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-image-2",
    prompt: "A green ceramic mug on a studio table",
    size: "1024x1024",
    n: 1,
    response_format: "b64_json",
    output_format: "png",
  }),
});

if (!response.ok) {
  throw new Error(await response.text());
}

const { data } = await response.json();
const b64Json = data[0].b64_json.replace(/^data:.*;base64,/, "");
await writeFile("output.png", Buffer.from(b64Json, "base64"));
```

<Warning>
  Не рассчитывайте, что `output_format: "jpeg"` или `output_format: "webp"` сразу вернет JPEG или WebP-файл. Текущий endpoint может по-прежнему вернуть PNG. Если продукту нужен JPEG или WebP, сначала получите PNG и конвертируйте его в своем коде.
</Warning>

## Поток ответа

Endpoint синхронный. После отправки `POST /images/generations` держите текущий HTTP-запрос открытым до ответа сервера. При успешной генерации содержимое изображения возвращается в `data[0].b64_json`.

Endpoint не возвращает `task_id`; отдельного status query или endpoint для скачивания результата нет.

## Timeout и повторные попытки

- Задавайте timeout HTTP-клиента в несколько минут.
- Повторяйте transport errors, `408`, `409`, `425`, `429` и `5xx`.
- Не повторяйте автоматически `400`, `401`, отсутствующие параметры и некорректные запросы.
- Используйте exponential backoff, например `3s`, `8s`, `15s`.
- Если дубли изображений недопустимы, записывайте собственный request ID перед retry.

## Обработка ошибок

Ошибка обычно возвращается как JSON. При отображении сообщения сначала прочитайте `error.message`, затем `message`, а после этого HTTP status text.

| HTTP status | Значение | Что делать |
| --- | --- | --- |
| `400` | Некорректный JSON, отсутствует параметр или неподдерживаемый размер | Проверьте тело запроса. Не повторяйте автоматически. |
| `401` | API Key отсутствует или недействителен | Проверьте header `Authorization: Bearer YOUR_API_KEY`. |
| `402` | Недостаточно баланса или квоты | Пополните баланс или используйте доступный key. |
| `429` | Rate limit, ограничение concurrency или занятый upstream | Подождите и повторите с exponential backoff. |
| `5xx` | Ошибка gateway или upstream | Повторите запрос. При повторной ошибке сохраните request ID и сообщение ошибки. |

## Чек-лист подключения

- Base URL — `{{openai-base-url}}`.
- Header содержит `Authorization: Bearer YOUR_API_KEY`.
- Request использует `application/json` и `POST /images/generations`.
- `model` — `gpt-image-2`, `response_format` — `b64_json`, `output_format` — `png`, `n` — `1`.
- `size` выбран из рекомендованных значений, например `1024x1024`.
- HTTP client допускает ожидание генерации в течение нескольких минут.
