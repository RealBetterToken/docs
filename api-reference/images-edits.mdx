`POST /v1/images/edits`

Endpoint image-to-image использует тело запроса `multipart/form-data`. Загрузите одно или несколько референсных изображений и передайте prompt и параметры как поля формы.

<Note>
  Используйте `{{openai-base-url}}` как `Base URL`. API Key BetterToken передается через `Authorization: Bearer YOUR_API_KEY`.
</Note>

<Tip>
  В Playground справа можно заполнить поля формы, загрузить референсные изображения и отправить запрос напрямую на `{{images-edits-url}}`.
</Tip>

<Warning>
  Не используйте обычное JSON-тело для image-to-image. Передавайте текстовые поля и файлы через `multipart/form-data`.
</Warning>

## Рекомендуемые значения

Передавайте эти поля явно в каждом запросе:

```text
model=gpt-image-2
n=1
response_format=b64_json
output_format=png
```

Для одного референсного изображения используйте `image`. Для нескольких референсных изображений используйте повторяющиеся поля `image[]`.

## Одно референсное изображение

```bash
curl '{{images-edits-url}}' \
  -H 'Authorization: Bearer sk-***REDACTED***' \
  -F 'model=gpt-image-2' \
  -F 'prompt=Используй это референсное изображение, чтобы создать более аккуратное квадратное главное изображение продукта, сохранив основной стиль.' \
  -F 'n=1' \
  -F 'size=1024x1024' \
  -F 'response_format=b64_json' \
  -F 'output_format=png' \
  -F 'image=@reference.png'
```

## Несколько референсных изображений

```bash
curl '{{images-edits-url}}' \
  -H 'Authorization: Bearer sk-***REDACTED***' \
  -F 'model=gpt-image-2' \
  -F 'prompt=Объедини эти референсные изображения в единый промо-постер с согласованным стилем.' \
  -F 'n=1' \
  -F 'size=1024x1024' \
  -F 'response_format=b64_json' \
  -F 'output_format=png' \
  -F 'image[]=@reference-1.png' \
  -F 'image[]=@reference-2.jpg' \
  -F 'image[]=@reference-3.png'
```

## Локальное редактирование по маске

Добавьте необязательное файловое поле `mask`, если нужно направить редактирование на выбранную область. Текущий endpoint BetterToken читает один PNG-файл `mask`. Не отправляйте повторяющиеся поля `mask[]`.

- Исходное изображение и mask должны иметь одинаковый формат и размеры в пикселях. Поскольку mask должна быть PNG, используйте PNG для обоих файлов. Размер каждого файла должен быть меньше 50 MB.
- Mask должна содержать Alpha-канал. Полностью прозрачные пиксели (`Alpha 0`) отмечают область, которую модель может перерисовать. Полностью непрозрачные пиксели (`Alpha 255`) направляют модель на сохранение области.
- Обычное чёрно-белое RGB-изображение не является корректной mask, если в файле нет Alpha-канала.
- Mask служит ориентиром для модели и не гарантирует, что пиксели за пределами прозрачной области останутся абсолютно неизменными.

```bash
curl '{{images-edits-url}}' \
  -H 'Authorization: Bearer sk-***REDACTED***' \
  -F 'model=gpt-image-2' \
  -F 'prompt=Replace only the masked area with a blue circle. Preserve everything else.' \
  -F 'n=1' \
  -F 'size=1024x1024' \
  -F 'response_format=b64_json' \
  -F 'output_format=png' \
  -F 'image=@original.png' \
  -F 'mask=@mask.png'
```

### Редактирование по маске на Python

Откройте оба файла в одном операторе `with`, чтобы Python закрыл их после запроса:

```python
import requests

url = "{{images-edits-url}}"
headers = {"Authorization": "Bearer sk-***REDACTED***"}
data = {
    "model": "gpt-image-2",
    "prompt": "Replace only the masked area with a blue circle. Preserve everything else.",
    "n": "1",
    "size": "1024x1024",
    "response_format": "b64_json",
    "output_format": "png",
}

with open("original.png", "rb") as image_file, open("mask.png", "rb") as mask_file:
    files = {
        "image": ("original.png", image_file, "image/png"),
        "mask": ("mask.png", mask_file, "image/png"),
    }
    response = requests.post(url, headers=headers, data=data, files=files, timeout=300)

response.raise_for_status()
result = response.json()
```

### Проверка файлов перед загрузкой

Этот минимальный пример с Pillow проверяет формат, размеры, Alpha-канал, а также наличие полностью прозрачных и полностью непрозрачных пикселей:

```python
from pathlib import Path
from PIL import Image

image_path = Path("original.png")
mask_path = Path("mask.png")

if image_path.stat().st_size >= 50 * 1024 * 1024 or mask_path.stat().st_size >= 50 * 1024 * 1024:
    raise ValueError("Each file must be smaller than 50 MB")

with Image.open(image_path) as image, Image.open(mask_path) as mask:
    if image.format != "PNG" or mask.format != "PNG":
        raise ValueError("The image and mask must both be PNG files")
    if image.size != mask.size:
        raise ValueError("The image and mask dimensions must match")
    if "A" not in mask.getbands():
        raise ValueError("The mask must contain an Alpha channel")
    if mask.getchannel("A").getextrema() != (0, 255):
        raise ValueError("The mask Alpha channel must contain both 0 and 255")
```

## Рекомендуемые размеры

| `size` | Соотношение | Сценарий |
| --- | --- | --- |
| `auto` | Auto | Автоматический выбор размера |
| `1024x1024` | `1:1` | Квадратные изображения, аватары, обложки, assets |
| `1536x1024` | `3:2` | Landscape-постеры, баннеры, сцены |
| `1024x1536` | `2:3` | Portrait-обложки для мобильных и постеры |
| `1536x1152` | `4:3` | Стандартные landscape-изображения, product images, content graphics |
| `1152x1536` | `3:4` | Стандартные portrait-изображения, mobile covers, vertical posters |
| `2048x2048` | `1:1` | High-resolution квадратные изображения |
| `2048x1152` | `16:9` | High-resolution landscape-изображения |
| `3840x2160` | `16:9` | 4K landscape-изображения |
| `2160x3840` | `9:16` | 4K portrait-изображения |

`size` задает ожидаемое соотношение сторон и уровень размера. Фактические пиксели в ответе могут быть сопоставлены или скорректированы сервером. Используйте размеры декодированного изображения, а не принудительную обрезку до запрошенного значения.

## Сохранение изображения

Успешный ответ следует OpenAI-совместимой форме image response:

```json
{
  "created": 1710000000,
  "data": [
    {
      "b64_json": "iVBORw0KGgoAAAANSUhEUgAA...(truncated)"
    }
  ]
}
```

Прочитайте `data[0].b64_json` и сохраните его как base64 image content. Всегда задавайте `output_format: "png"`, чтобы сохранить декодированное изображение как `.png`.

## Поток ответа

Endpoint синхронный. После отправки `POST /images/edits` держите текущий HTTP-запрос открытым до ответа сервера. При успешной генерации содержимое изображения возвращается в `data[0].b64_json`.

Endpoint не возвращает `task_id`; отдельного status query или endpoint для скачивания результата нет.
