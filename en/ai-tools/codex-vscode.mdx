The Codex VS Code Extension shares `~/.codex/config.toml` with Codex CLI/App. Use this page when you need to keep the official login, plugins, or Remote Control.

## Key settings

| Field | Value |
| --- | --- |
| API Key | `experimental_bearer_token = "YOUR_API_KEY"` |
| Base URL | `{{openai-base-url}}` |
| Model | `YOUR_MODEL_ID` |

## Prerequisites

- Install the latest Codex VS Code Extension
- Complete the official login in the Extension or Codex App
- <a href={"{{register-url}}"}>Create a BetterToken API Key</a>
- Copy a Model ID from the <a href={"{{model-plaza-url}}"}>model plaza</a> or key **Setup** dialog

## Install

Install the extension from the VS Code Marketplace, then restart VS Code.

## Manual setup

### Configure the Extension

Edit `~/.codex/config.toml`:

```toml
model_provider = "custom"
model = "YOUR_MODEL_ID"
review_model = "YOUR_MODEL_ID"
model_reasoning_effort = "high"

[model_providers.custom]
name = "BetterToken"
base_url = "{{openai-base-url}}"
wire_api = "responses"
requires_openai_auth = true
experimental_bearer_token = "YOUR_API_KEY"
```

Save the file, run **Developer: Reload Window** in VS Code, and reopen the Codex panel.

<Note>
  `requires_openai_auth = true` preserves the official login. `experimental_bearer_token` authenticates BetterToken model requests. Do not write the BetterToken API Key to `auth.json`.
</Note>

### Do not combine CLI/App and Extension authentication

| Scenario | Authentication fields |
| --- | --- |
| Codex CLI/App custom provider only | `env_key = "BETTERTOKEN_API_KEY"` and `requires_openai_auth = false` |
| Extension with official login | `requires_openai_auth = true` and `experimental_bearer_token = "YOUR_API_KEY"` |

Both alternatives use `[model_providers.custom]`. Keep only one table in a TOML file.

## Verify the connection

Create a new Extension session and send a short task. A response from `YOUR_MODEL_ID` while plugins and Remote Control remain available confirms the setup.

## Switch models

Change `model` and, optionally, `review_model`, then run **Developer: Reload Window**. Use a Model ID from the Setup dialog or model plaza.

## Common errors

| Error | Fix |
| --- | --- |
| Extension asks you to sign in again | Restore the official login and keep `requires_openai_auth = true`. |
| `401` or `403` | Copy `experimental_bearer_token` again; do not overwrite `auth.json`. |
| Duplicate table | Remove the other `[model_providers.custom]` table and keep one authentication mode. |
| Model not found | Replace `YOUR_MODEL_ID` with a current complete Model ID. |
| Configuration not applied | Save the file and run **Developer: Reload Window**. |

## Technical details

<Accordion title="Why Extension authentication differs from CLI/App">
  The Extension uses the official login for some Codex product features, so this setup keeps `requires_openai_auth = true`. A pure CLI/App custom provider uses an environment variable and `requires_openai_auth = false`. Both send OpenAI Responses requests through `{{openai-base-url}}`.
</Accordion>
