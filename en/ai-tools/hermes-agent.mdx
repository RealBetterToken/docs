To connect Hermes Agent to BetterToken, prepare an API key, enter the Base URL shown below, and choose a current Model ID from the model plaza.

## Key settings

| Field | Value |
| --- | --- |
| API Key | BetterToken API key |
| Base URL | `{{openai-base-url}}` |
| Model | A current Model ID from the <a href={"{{model-plaza-url}}"}>model plaza</a> |

## Prerequisites

- The current version of the tool is installed
- A BetterToken API key: <a href={"{{register-url}}"}>register and get one</a>
- A Model ID from the <a href={"{{model-plaza-url}}"}>model plaza</a>

### Additional requirements

- The selected Model ID comes from the **supported provider**
- macOS, Linux, Windows 10/11, or WSL2
- A model with at least a 64K context window for Hermes Agent tool use

## Install

### Install Hermes Agent

<Tabs>
  <Tab title="Desktop (macOS / Windows)">
    Hermes recommends the Desktop installer for macOS and Windows. [Download Hermes Desktop](https://hermes-agent.nousresearch.com/) and run the installer for your operating system.
  </Tab>

  <Tab title="Linux / macOS / WSL2">
    ```bash
    curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
    ```

    When installation finishes, open a new terminal or reload your shell before running `hermes`.
  </Tab>

  <Tab title="Windows PowerShell">
    Hermes Agent supports native Windows 10 and Windows 11. Open PowerShell or Windows Terminal and run:

    ```powershell
    iex (irm https://hermes-agent.nousresearch.com/install.ps1)
    ```

    Administrator rights are not required. Open a new PowerShell window after installation so the updated User PATH is available.
  </Tab>
</Tabs>

Verify the installation:

```bash
hermes --version
hermes doctor
```

<Note>
  WSL2 remains supported, but it is optional. Use it when you specifically need a Linux environment or the web dashboard's embedded terminal pane.
</Note>

## Manual setup

Use the interactive Hermes Agent model setup as the primary path. Edit the configuration files only when you need a manual setup.

| Field | Value |
| --- | --- |
| API Key | BetterToken API key |
| Base URL | `{{openai-base-url}}` |
| Model | A current Model ID from the <a href={"{{model-plaza-url}}"}>model plaza</a> |

### Setup

<Tabs>
  <Tab title="Interactive setup">
    <Steps>
      <Step title="Run the model selector">
        Exit any active Hermes chat first, then run:

        ```bash
        hermes model
        ```
      </Step>

      <Step title="Choose Custom endpoint">
        Select **Custom endpoint (self-hosted / VLLM / etc.)** from the provider list.
      </Step>

      <Step title="Fill in the BetterToken config">
        Enter:

        - **Base URL**: `{{openai-base-url}}`
        - **API Key**: your BetterToken API Key
        - **Model**: a **model ID from a supported provider** copied from the <a href={"{{model-plaza-url}}"}>model plaza</a>

        If Hermes asks for an API mode, choose the OpenAI-compatible Chat Completions option. If it asks for context length, use the value published for that model and make sure it is at least 64K.
      </Step>

      <Step title="Start Hermes Agent">
        ```bash
        hermes --tui
        ```

        You can also run `hermes` to use the classic terminal interface.
      </Step>
    </Steps>
  </Tab>

  <Tab title="Config files">
    The interactive setup is safer because it validates and stores the endpoint for you. For a manual setup, add the non-secret model settings to `~/.hermes/config.yaml`:

    ```yaml
    model:
      default: YOUR_MODEL_ID
      provider: custom
      base_url: "{{openai-base-url}}"
    ```

    Store the API Key separately in `~/.hermes/.env`:

    ```dotenv
    OPENAI_API_KEY=YOUR_API_KEY
    ```

    On native Windows, these files live under `%LOCALAPPDATA%\hermes\` instead of `~/.hermes/`. Replace `YOUR_MODEL_ID` and `YOUR_API_KEY`, then run `hermes doctor` before starting Hermes.
  </Tab>
</Tabs>

### Migrate from OpenClaw

If you already use OpenClaw, first check whether your current Hermes Agent version provides the migration command. Run a dry run before changing anything.

```bash
hermes claw migrate --dry-run
```

After you confirm the output, run the migration:

```bash
hermes claw migrate
```

After migration, still review the Hermes Agent **Base URL**, API Key, and model ID. They should match `{{openai-base-url}}`, your BetterToken API Key, and a model ID from a supported provider.

## Verify the connection

Start Hermes with `hermes --tui` or `hermes`, then send this short prompt:

```text
Reply with HERMES_OK only. Do not use tools.
```

The connection works when Hermes returns `HERMES_OK` without an authentication, endpoint, or Model ID error. Then try one small read-only task before enabling gateways, scheduled tasks, or additional tools.

## Switch models

Run `hermes model` outside a chat to add or reconfigure a provider. Inside an active chat, use `/model` to switch between providers and models you already configured. Use the exact Model ID from the <a href={"{{model-plaza-url}}"}>model plaza</a>.

## Common errors

| Error | What to check |
| --- | --- |
| `401` or `Unauthorized` | Check the BetterToken API key and remove leading or trailing spaces. |
| `404` | Check the Base URL and do not append a specific endpoint path. |
| `model not found` | Copy a current Model ID from the model plaza. |
| `hermes: command not found` | Open a new terminal after installation, then check the PATH. |
| Configuration error after update | Run `hermes config check`, then `hermes config migrate` if prompted. |


### Troubleshooting

- If requests fail or return no response, confirm that **Base URL** is exactly `{{openai-base-url}}`. Do not append `/chat/completions` in this field.
- If Hermes reports that the model does not exist, confirm that **Model** is a model ID from a supported provider from the <a href={"{{model-plaza-url}}"}>model plaza</a>.
- If authentication fails, check for copied spaces and confirm that the selected Model ID comes from the **supported provider**.
- If Hermes still uses the old model, exit the chat, run `hermes model`, save the custom endpoint again, and start a new chat.
- BetterToken usually does not require an extra `User-Agent` or custom headers. Only add headers when your custom gateway, tenant routing, observability, or caching layer explicitly requires them.

<Note>
  Do not commit real API Keys to your repository. For team-shared setup, prefer environment variables or local config.
</Note>
