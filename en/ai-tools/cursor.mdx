When connecting BetterToken to Cursor, use the OpenAI Base URL. External tools now use the Codex group, so copy the current model ID from the [model plaza](https://www.bettertoken.ai/pricing).

<Warning>
  Cursor's custom API key, custom model, and Base URL capabilities depend on the current client version and plan. If an option is missing, follow what your Cursor version actually supports.
</Warning>

## Prerequisites

- Cursor installed ([download Cursor](https://www.cursor.com))
- BetterToken API Key ([register here](https://www.bettertoken.ai/register))

## Setup

<Steps>
  <Step title="Open the model settings page">
    In Cursor, open **Settings** and go to **Models**.
  </Step>

  <Step title="Configure the BetterToken API">
    In **API Keys**:

    1. Enable **Override OpenAI Base URL**
    2. Enter `https://www.bettertoken.ai/v1`
    3. Paste your BetterToken API Key into **OpenAI API Key**
    4. Complete the verification flow
  </Step>

  <Step title="Add a model">
    In **Models**, click **View All Models**, then **Add Custom Model**.

    Paste a current **Codex group** model ID copied from the [model plaza](https://www.bettertoken.ai/pricing).
  </Step>

  <Step title="Only configure extra headers when the official docs explicitly require them">
    The official Cursor API key docs do not list an extra `User-Agent` as a required BetterToken or OpenAI-compatible setup step. You usually do not need extra headers for BetterToken.

    If you are also using a custom gateway, tenant routing, observability, or caching layer, add headers only according to that upstream service's official docs.
  </Step>

  <Step title="Restart Cursor">
    After changing the config, fully quit and reopen Cursor before selecting the model you added.
  </Step>

  <Step title="Select the model and start using it">
    Choose the model you just added in the Cursor chat panel.
  </Step>
</Steps>

## Notes

- Do not keep using hardcoded Claude model names
- If you need extra headers, follow the current Cursor docs or your upstream gateway requirements instead of assuming `User-Agent` is mandatory for BetterToken
