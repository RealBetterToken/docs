In OpenClaw, “configured successfully” and “the current agent or current session is actually using it” are not the same thing. The core setup is to use the Base URL `https://www.bettertoken.ai/v1` and a model ID from the [model plaza](https://www.bettertoken.ai/pricing) in the **Codex group**. The provider type and API protocol depend on your current OpenClaw version and provider implementation, so do not treat `Codex provider + OpenAI Responses` as the only valid path.

<Warning>
  OpenClaw's official docs describe `models.providers.*.headers` as optional custom auth or proxy-routing configuration, and they explicitly note that OpenClaw's hidden `User-Agent` only applies to native OpenAI / OpenAI Codex traffic, not to OpenAI-compatible proxies such as BetterToken.
</Warning>

## Prerequisites

- OpenClaw installed
- BetterToken API Key ([register here](https://www.bettertoken.ai/register))

        - **Provider type**: `Codex provider` or `custom provider`
        - **API protocol**: use whatever matches your current OpenClaw version and provider implementation
        - **Model**: a currently available model ID copied from the [model plaza](https://www.bettertoken.ai/pricing)

        In some stable setups, the provider is stored as a custom provider and the runtime may show `openai-completions`. As long as the Base URL and model ID are correct, that difference in display usually does not break the setup.

      <Step title="Only configure `headers` when you need custom auth or proxy routing">
        OpenClaw's official docs support extra headers in `models.providers.*.headers`, but this is optional. You usually do not need an extra `User-Agent` when connecting BetterToken.

      </Step>

        ```bash
        openclaw models set <provider>/<Codex model ID copied from https://www.bettertoken.ai/pricing>
        openclaw gateway restart
        openclaw models status
        ```

        This only confirms that the config was written. It does not mean the current Discord session already switched to BetterToken.
      </Step>

### Notes for multi-agent setups and existing sessions

The effective model priority in OpenClaw is usually:

`session override` > `agents.list[*].model` > `agents.defaults.model.primary`

This means:

- If an agent explicitly defines `model` in `agents.list`, it does not inherit the global default model.
- If you set BetterToken as the global default model but `main` still pins an older model, Discord DM flows that use `main` still keep using the older model.
- If a previous session still has `providerOverride`, `modelOverride`, or `authProfileOverride`, the current session may keep using the old route even after you update the default model.

Existing sessions do not automatically inherit a new default model.

Recommended workflow:

1. If you want `main` to follow the global default, do not set a separate `model` for `main`, or change it to BetterToken.
2. Run `openclaw gateway restart` after changing the config.
3. Run `/new` in Discord to start a fresh session.
4. Use `/status` and `/model` to verify the active model.

### Minimal config example

Use the provider id shown by `openclaw models list`. The example below uses `bettertoken/gpt-5.4`; replace it if your provider id is different.

```json
{
  "agents": {
    "defaults": {
      "model": {
        "primary": "bettertoken/gpt-5.4",
        "fallbacks": []
      },
      "models": {
        "bettertoken/gpt-5.4": {
          "alias": "bettertoken"
        }
      }
    },
    "list": [
      {
        "id": "main"
      },
      {
        "id": "fitness-coach"
      },
      {
        "id": "trade-recorder",
        "model": {
          "primary": "bettertoken/gpt-5.4",
          "fallbacks": []
        }
      }
    ]
  }
}
```

- `main` does not define `model`, so it inherits the global BetterToken default.
- `trade-recorder` defines `model`, so it does not follow later changes to the global default.

## Make it take effect

<Tip>
  If `/model` is unstable, hot reload is inconsistent, or the model picker behaves strangely on an older OpenClaw build, upgrade to the latest version before deeper troubleshooting.
</Tip>

<Steps>
  <Step title="Verify the config layer first">
    Run:

    ```bash
    openclaw models list
    openclaw models status
    ```

    Confirm the BetterToken provider exists and the default model points to BetterToken.
  </Step>

  <Step title="Reload the gateway">
    ```bash
    openclaw gateway restart
    ```
  </Step>

  <Step title="Start a new session">
    Run `/new` in Discord.

    Changing the default model does not automatically update an existing session.
  </Step>

  <Step title="Verify the model used by the current session">
    Run `/status` in Discord and confirm the current agent and current session are using BetterToken.
  </Step>

  <Step title="Check the available model picker if needed">
    Run `/model` in Discord.

    If BetterToken does not appear there, check:

    - whether the current model is listed in `agents.defaults.models`
    - whether the provider model has a readable display name and, if needed, an `alias` in `agents.defaults.models`
    - whether you already ran `openclaw gateway restart`
    - whether you already ran `/new`
  </Step>
</Steps>

## Troubleshooting shortcuts

- If you changed the default model but runtime still uses the old one, check `agents.list.main.model` first
- If BetterToken does not appear in `/model`, check whether it is listed in `agents.defaults.models`
- If Discord still shows the old route after a config change, run `openclaw gateway restart` and then `/new`
- If the model picker or hot reload still looks stale, upgrade OpenClaw first and test again
