## Short answer

`model_provider` tells Codex CLI which provider to use. Its value must match a provider id defined under `[model_providers.<id>]`.

`base_url` is the API endpoint where model requests are sent. For an OpenAI-compatible provider, it usually points to a `/v1` style endpoint.

`wire_api` tells Codex which protocol shape to use when talking to that provider. In the Codex configuration reference, `responses` is a supported provider protocol value.

## When this matters

- You are configuring a custom OpenAI-compatible provider
- Codex says the provider cannot be found or model requests fail
- You are not sure how `model_provider` differs from `model`
- You are putting BetterToken, OpenAI, or another provider in one `config.toml`
- You need to separate Base URL, API Key, and Model ID

## Field relationships

| Field | Purpose |
| --- | --- |
| `model_provider` | Selects the active provider id |
| `[model_providers.<id>]` | Defines one provider's detailed configuration |
| `name` | Display name for the provider |
| `base_url` | Root API endpoint |
| `wire_api` | Provider protocol, commonly `responses` |
| `model` | Default main model ID |
| `review_model` | Model used for code review flows such as `/review` |

## Locate and back up your files

If you use a custom `CODEX_HOME`, edit `config.toml` and `auth.json` in that directory. Otherwise use `~/.codex` on macOS / Linux or `%USERPROFILE%\.codex` on Windows. CLI and App must use the same directory. WSL has its own user directory.

Fully quit Codex before editing. Back up both files to a private location. Create missing files if needed. Replace existing settings instead of appending duplicate keys or tables; keep unrelated settings.

<Warning>
  This switches from ChatGPT login to API Key authentication. It does not preserve official account access. Protect `auth.json` and its backups; never commit or share them.
</Warning>

## Recommended pattern

### Edit config.toml

Put `model_provider`, `model`, and `cli_auth_credentials_store` at the top level, before all TOML tables, not under a profile. The selected provider ID must match its table name. For this file-auth setup, remove `env_key` and `experimental_bearer_token` from the selected provider.

```toml
model_provider = "bettertoken"
model = "gpt-6-astra"
cli_auth_credentials_store = "file"

[model_providers.bettertoken]
name = "BetterToken"
base_url = "{{openai-base-url}}"
wire_api = "responses"
requires_openai_auth = true
request_max_retries = 4
stream_max_retries = 8
stream_idle_timeout_ms = 300000
supports_websockets = false
```

This example uses GPT-6 Astra (`gpt-6-astra`). For another model, copy its complete ID from the <a href={"{{model-plaza-url}}"}>model plaza</a> and replace `model`. GPT, Kimi, and GLM use the same file-auth structure; automatic setup is available for GPT.

### Edit auth.json

`auth.json` is in the same directory as `config.toml`. If `auth.json` does not exist, create it in that directory. Set its contents to the following JSON, replace `YOUR_API_KEY` with your BetterToken API Key, and save the file.

```json
{
  "auth_mode": "apikey",
  "OPENAI_API_KEY": "YOUR_API_KEY"
}
```

## Restart and verify

Save both files. In the terminal, start a new Codex CLI session directly:

```bash
codex
```

Fully quit Codex App, including background processes, then reopen it and create a new local task. Send a short prompt in each client you use. A normal response verifies that client's connection.

## Troubleshooting

For `401`, `403`, or a sign-in prompt, check the active directory, the Key in `auth.json`, `auth_mode = apikey`, `cli_auth_credentials_store = file`, and `requires_openai_auth = true`. For provider or model errors, check the matching provider ID, `{{openai-base-url}}`, `wire_api = responses`, and the model's availability. If changes do not apply, check configuration overrides and confirm CLI and App use the same `CODEX_HOME`.
