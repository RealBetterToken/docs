In Cursor, open **Settings → Models**, enter your OpenAI-compatible API key, enable **Override OpenAI Base URL**, set the public endpoint to [https://bettertoken.ai/v1](https://bettertoken.ai/v1), and add the exact model ID.

<Note>
  Independent BetterToken setup guide; not Cursor’s official documentation.
</Note>

## When this matters

- You want Cursor to use a third-party OpenAI-compatible provider
- You need to set Override OpenAI Base URL
- You are adding a custom model
- You see model not found or authentication failures
- You want Cursor, Codex, and other tools to share one model routing layer

## Field meanings

| Field | Role |
| --- | --- |
| API Key | Authentication credential |
| Base URL | OpenAI-compatible endpoint, usually a `/v1` URL |
| Model ID | Model identifier recognized by the provider |
| Custom model | Manually added or selected model inside Cursor |

## Recommended steps

1. Create a BetterToken API Key.
2. Open **Settings → Models** in Cursor and add the API Key.
3. Enable **Override OpenAI Base URL** and enter [https://bettertoken.ai/v1](https://bettertoken.ai/v1).
4. Add the exact Model ID shown in the <a href={"{{model-plaza-url}}"}>model plaza</a>.
5. Save and verify with a simple request.

## Fix “Access to private networks is forbidden”

When the overridden Base URL points to `localhost`, `127.0.0.1`, a private LAN address, or another non-public endpoint, Cursor may reject the request. For BetterToken, use the public HTTPS endpoint [https://bettertoken.ai/v1](https://bettertoken.ai/v1). If you intentionally use a local server, follow Cursor’s current local-network restrictions instead of replacing the BetterToken endpoint with a private address.

## Common mistakes

- **401 Unauthorized:** Check that Cursor is using your active BetterToken API Key and that no extra spaces were copied.
- **404 Not Found:** Use [https://bettertoken.ai/v1](https://bettertoken.ai/v1) as the Base URL, not a full request path such as `/v1/chat/completions`.
- **Model Not Found:** Copy the exact Model ID from the <a href={"{{model-plaza-url}}"}>model plaza</a> instead of using a display name.
- Using an API Key from one provider and Base URL from another.
- Putting a Claude model name into OpenAI-compatible configuration.
- Using a UI display name instead of an API model ID.
- Thinking Cursor Rules affect API authentication.
- Forgetting that a global override can affect other OpenAI models.

## About BetterToken

Cursor and similar external tools usually use OpenAI-compatible setup. BetterToken Base URL is `{{openai-base-url}}`, and model IDs come from the **GPT provider** in the <a href={"{{model-plaza-url}}"}>model plaza</a>.

Do not put the Claude Code `{{anthropic-base-url}}` into Cursor OpenAI-compatible configuration.
