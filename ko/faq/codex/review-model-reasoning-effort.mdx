## 짧은 답변

`review_model`은 `/review`에 사용할 모델을 지정합니다. 설정하지 않으면 Codex는 현재 세션 모델을 사용합니다. `model_reasoning_effort`는 Responses API에서 이 설정을 지원하는 모델의 추론 강도를 조정합니다.

강도를 높이면 어려운 작업에 도움이 될 수 있지만, 정답이나 더 낮은 총비용을 보장하지는 않습니다. 온도나 답변 길이 설정도 아닙니다.

## Field 관계

| Field | 역할 |
| --- | --- |
| `model` | 일반 작업용 default model |
| `review_model` | `/review` 등의 review workflows에 사용하는 model |
| `model_reasoning_effort` | main model의 reasoning strength |
| `/model` | model 또는 reasoning changes의 in-session entry point |
| `/review` | Codex에게 current changes를 review하도록 요청하는 entry point |

## 작업에 맞는 추론 강도 선택

다음 설정을 시작점으로 삼고 작업의 완료 기준에 따라 결과를 평가하세요.

| 작업 | 시작 설정 | 확인할 내용 |
| --- | --- | --- |
| 범위가 명확한 작은 수정이나 짧은 설명 | 지원하는 경우 `low` | 정확성과 응답 시간. |
| 일반적인 기능 개발이나 재현 방법이 명확한 버그 | 지원하는 경우 `medium` | 테스트, 누락, 불필요한 변경. |
| 어려운 원인 분석, 여러 모듈 변경, 상세 검토 | 먼저 `high`, 필요하면 지원하는 상위 단계 | 놓친 제약, 잘못된 지적, 사용 가능한 결과까지의 총시간. |

선택 가능한 단계는 모델, Codex 버전, 제공업체에 따라 달라집니다. `xhigh`나 `max`를 쓰기 전에 `/model`의 선택지와 해당 모델의 공식 문서를 확인하세요. 한 모델의 지원 여부가 다른 모델에도 적용되지는 않습니다. 강도를 높이면 추론 토큰과 지연 시간이 늘 수 있으며, 재시도, 컨텍스트 크기, 도구 호출, 요금 방식도 총비용에 영향을 줍니다.

## 설정 예시

지속적으로 사용할 기본값은 `CODEX_HOME`의 `config.toml`에 설정하세요. 변수가 없으면 `~/.codex/config.toml`을 사용합니다. 이 키는 모든 TOML 테이블 앞의 최상위에 두고 제공업체와 인증 설정은 유지하세요.

```toml
model = "gpt-6-astra"
review_model = "gpt-6-astra"
model_reasoning_effort = "high"
```

## 파일 기본값과 세션 설정

시작할 때 CLI 인수와 `-c` 설정이 신뢰한 프로젝트 설정, 선택한 프로필, 사용자 기본값보다 우선합니다. 현재 Codex의 `--profile NAME`은 `CODEX_HOME`에서 `NAME.config.toml`을 읽습니다. 이전 버전은 다른 프로필 형식을 사용했습니다.

이번 실행에서만 추론 강도를 바꾸려면 다음을 실행하세요.

```bash
codex -c 'model_reasoning_effort="medium"'
```

세션 중에는 `/model`로 현재 모델과 지원되는 추론 단계를 선택하세요. 파일을 수정해도 실행 중인 세션이 즉시 바뀐다고 보장할 수 없습니다. 저장된 기본값은 새 세션에서 확인하세요. Plan 모드는 `plan_mode_reasoning_effort`나 자체 기본 설정을 쓸 수 있으므로 별도로 확인해야 합니다.

## 실제 적용된 설정 확인

1. `codex --version`을 실행한 뒤 대상 프로젝트 디렉터리에서 새 세션을 시작하세요.
2. `/model`로 선택한 강도를, `/status`로 현재 모델과 세션 설정을 확인하세요. 파일과 다르면 시작 인수, 선택한 프로필, 프로젝트 설정, 그리고 지원되는 경우 `/debug-config`를 확인하세요.
3. 별도 세션에서 동일한 대표 작업을 지원되는 두 단계로 비교하세요. diff, 테스트, 완료 시간, BetterToken 사용량 기록을 확인하고 품질 목표를 충족하는 설정을 선택하세요. 강도를 낮춰도 총비용이 줄어든다는 보장은 없습니다.

## 일반적인 실수

- `review_model`이 모든 tasks에서 main model을 대체한다고 생각함
- reasoning effort를 temperature setting으로 취급함
- current provider가 지원하지 않는 model ID 사용
- 모든 task에 highest reasoning effort 사용
- actual usage와 result quality를 확인하지 않고 model names만 봄

## BetterToken 정보

서로 다른 models와 reasoning settings는 usage에 영향을 줍니다. BetterToken usage records는 real tasks 간 input, output 및 cost를 비교하는 데 도움을 줍니다.

current provider가 인식하도록 **GPT provider**에서 model IDs를 복사하세요.
