## Réponse courte

Cursor Rules indique à Cursor comment travailler dans un projet. `AGENTS.md` est un fichier d’instructions de dépôt que de nombreux agents de programmation peuvent lire. `.cursorignore` contrôle les fichiers ou répertoires que Cursor ne doit pas indexer ni lire.

Ils concernent tous le contexte du projet, mais résolvent des problèmes différents : Rules guide le comportement, `AGENTS.md` donne des instructions inter-agents et `.cursorignore` exclut du contenu.

## Comparaison

| Fichier / fonctionnalité | Rôle principal |
| --- | --- |
| Cursor Rules | Règles de projet, d’équipe ou d’utilisateur pour Cursor |
| `AGENTS.md` | Instructions de dépôt inter-agents et règles de collaboration |
| `.cursorignore` | Fichiers ou répertoires que Cursor doit ignorer |
| API Key / Base URL | Configuration des requêtes de modèles, pas règles de projet |

## Contenu adapté à Rules

- Style de code du projet
- Conventions du framework
- Règles concernant les composants et répertoires
- Exigences de test et de validation
- Comportement de modification de Cursor

## Contenu adapté à .cursorignore

- Gros artefacts de build
- Répertoires de dépendances
- Fichiers générés
- Répertoires sensibles qui ne doivent pas être indexés
- Fichiers volumineux sans lien avec le développement actuel

## Erreurs fréquentes

- Écrire des API Keys dans Rules ou `AGENTS.md`.
- Traiter `.cursorignore` comme un système de sécurité complet.
- Conserver des règles obsolètes qui induisent l’IA en erreur.
- Penser que la configuration de Base URL remplace les règles de projet.
- Confondre Cursor Rules avec le fichier `CLAUDE.md` de Claude Code.

## À propos de BetterToken

BetterToken gère l’accès à l’API de modèles et la visibilité sur l’utilisation. Cursor Rules, `AGENTS.md` et `.cursorignore` gèrent le contexte du projet et le comportement de modification.

L’accès API n’est que la première étape. La qualité des résultats à long terme dépend fortement de règles claires et d’un contexte maîtrisé.
