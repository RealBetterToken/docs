## Réponse courte

Ne choisissez pas uniquement selon le nom du modèle. Vérifiez d’abord le protocole et le fournisseur requis par votre outil. Comparez ensuite le type de tâche, la qualité, la vitesse, la longueur du contexte et le coût.

Avec BetterToken, Claude Code doit généralement utiliser le **fournisseur Claude**. Codex CLI, Cursor, Cline, OpenCode, OpenClaw et les autres outils externes doivent généralement utiliser le **fournisseur GPT**. Copiez le Model ID depuis le <a href={"{{model-plaza-url}}"}>model plaza</a>.

## Quand ces informations sont utiles

- Vous ne savez pas s’il faut utiliser le **fournisseur Claude** ou le **fournisseur GPT**
- Vous alternez entre Claude Code, Codex CLI, Cursor, Cline ou des outils similaires
- Un modèle fonctionne, mais il est trop coûteux, trop lent ou offre trop peu de contexte
- Vous recherchez un modèle moins cher pour les traitements par lots
- Vous souhaitez connecter la même gateway API à plusieurs outils de développement assisté par IA

## Commencer par l’outil, puis choisir le modèle

Ne commencez pas par comparer les classements des modèles. Vérifiez d’abord le protocole attendu par le client.

| Cas d’utilisation | Fournisseur recommandé | Base URL habituelle |
| --- | --- | --- |
| Claude Code | Fournisseur Claude | `{{anthropic-base-url}}` |
| Claude Desktop Gateway | Fournisseur Claude ou groupe requis par la gateway locale | Suivez la configuration de la gateway |
| Codex CLI | Fournisseur GPT | `{{openai-base-url}}` |
| Cursor | Fournisseur GPT | `{{openai-base-url}}` |
| Cline | Fournisseur GPT | `{{openai-base-url}}` |
| OpenCode / OpenClaw | Fournisseur GPT | `{{openai-base-url}}` |

Si le protocole ou le fournisseur est incorrect, le modèle peut exister, mais la requête peut échouer avec `model not found`, une erreur d’authentification ou un format de requête invalide.

## Choisir selon le type de tâche

| Type de tâche | Critères prioritaires |
| --- | --- |
| Programmation complexe, architecture et tâches longues | Qualité du raisonnement, fenêtre de contexte et stabilité des appels d’outils |
| Questions quotidiennes et génération légère | Vitesse et coût |
| Traduction, classification et résumés par lots | Prix unitaire, débit et stabilité |
| Revue de code et documentation technique | Compréhension du code, contexte long et stabilité des sorties |
| Tâches exploratoires | Commencez avec un modèle de coût intermédiaire, puis passez à un modèle plus performant pour les étapes critiques |

N’envoyez pas toutes les tâches au modèle le plus coûteux par défaut. De nombreux traitements par lots ne nécessitent ni raisonnement approfondi ni forte créativité. Des modèles plus rapides et moins chers sont souvent mieux adaptés.

## Workflow recommandé

1. Vérifiez si l’outil accepte une API compatible avec OpenAI ou Anthropic.
2. Choisissez le **fournisseur Claude** ou le **fournisseur GPT** selon l’outil.
3. Copiez le Model ID actuel depuis le <a href={"{{model-plaza-url}}"}>model plaza</a>.
4. Testez la qualité, la vitesse et le coût avec une petite tâche.
5. Vérifiez l’utilisation dans le Dashboard avant d’adopter ce modèle à long terme.
6. Conservez un modèle de secours plus performant pour les tâches complexes au lieu de n’en configurer qu’un seul.

## Erreurs fréquentes

- Consulter uniquement le nom affiché sans vérifier le Model ID.
- Utiliser un modèle du **fournisseur Claude** dans un outil GPT ou compatible avec OpenAI.
- Utiliser un modèle du **fournisseur GPT** dans une configuration Claude Code compatible avec Anthropic.
- Supposer que le modèle le plus récent convient toujours à toutes les tâches.
- Comparer uniquement la qualité des sorties sans tenir compte de la longueur du contexte, de la vitesse et du coût.
- Basculer le trafic de production vers un nouveau modèle sans effectuer d’abord un petit test.

## À propos de BetterToken

BetterToken centralise la gestion des API Key, du solde et des relevés d’utilisation. Vous pouvez gérer les appels de modèles depuis le même Dashboard, mais chaque outil doit toujours utiliser le protocole et le fournisseur qu’il prend en charge.

Règle rapide :

- Claude Code utilise le **fournisseur Claude** et `{{anthropic-base-url}}`
- Codex CLI, Cursor, Cline, OpenCode et OpenClaw utilisent le **fournisseur GPT** et `{{openai-base-url}}`
