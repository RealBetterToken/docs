Pour connecter Kilo Code à BetterToken, préparez une API Key, saisissez la Base URL ci-dessous et choisissez un Model ID actuel dans le model plaza.

La configuration tient en trois étapes : choisissez un fournisseur compatible avec OpenAI, saisissez la BetterToken API Key et la Base URL, puis sélectionnez un Model ID actuel. Envoyez ensuite une première requête courte pour vérifier la connexion.

## Paramètres principaux

| Champ | Valeur |
| --- | --- |
| API Key | BetterToken API Key |
| Base URL | `{{openai-base-url}}` |
| Model | Un Model ID actuel du <a href={"{{model-plaza-url}}"}>model plaza</a> |

## Prérequis

- La version actuelle de l’outil est installée
- Une BetterToken API Key : <a href={"{{register-url}}"}>inscrivez-vous pour en obtenir une</a>
- Un Model ID du <a href={"{{model-plaza-url}}"}>model plaza</a>

### Exigences supplémentaires

- VS Code est installé

## Installation

Si Kilo Code est déjà installé, passez directement à la [configuration manuelle](#configuration-manuelle) pour saisir votre BetterToken API Key, la Base URL et le Model ID.

Si vous devez encore installer l’extension ou souhaitez comprendre le contexte d’installation et d’utilisation régionale, consultez le [guide en anglais sur l’installation et l’API personnalisée de Kilo Code](https://bettertoken.ai/en/blog/kilo-code-russia-api-setup/), puis revenez ici pour utiliser les champs de configuration actuels.

## Configuration manuelle

Effectuez cette configuration dans l’interface des paramètres Kilo Code. Vous n’avez pas besoin de modifier de fichier de configuration.

| Champ | Valeur |
| --- | --- |
| API Key | BetterToken API Key |
| Base URL | `{{openai-base-url}}` |
| Model | Un Model ID actuel du <a href={"{{model-plaza-url}}"}>model plaza</a> |

### Configuration

<Steps>
  <Step title="Effacer les variables d’environnement en conflit">
    ```bash
    unset OPENAI_API_KEY
    unset OPENAI_BASE_URL
    ```
  </Step>

  <Step title="Ouvrir les paramètres Kilo Code">
    Ouvrez l’interface des paramètres Kilo Code.
  </Step>

  <Step title="Configurer le fournisseur d’API">
    Renseignez :

    - **API Provider** → `OpenAI Compatible`
    - **Base URL** → `{{openai-base-url}}`
    - **API Key** → votre BetterToken API Key
    - **Model** → un **model ID d’un fournisseur compatible** copié depuis le <a href={"{{model-plaza-url}}"}>model plaza</a>
  </Step>

  <Step title="Configurer des en-têtes supplémentaires uniquement si la documentation officielle l’exige explicitement">
    La documentation officielle Kilo Code consultée mentionne des en-têtes personnalisés facultatifs pour les fournisseurs OpenAI compatibles, mais ne présente pas `User-Agent` comme une étape obligatoire de configuration BetterToken.

    Si vous utilisez aussi une passerelle personnalisée, un routage de locataire, une couche d’observabilité ou de cache, ajoutez des en-têtes uniquement selon la documentation officielle de ce service en amont.
  </Step>

  <Step title="Redémarrer Kilo Code">
    Après avoir modifié la configuration, redémarrez VS Code ou rechargez l’extension Kilo Code pour appliquer les nouveaux paramètres.
  </Step>
</Steps>

<Note>
  Si vous avez besoin d’en-têtes supplémentaires, suivez la documentation actuelle de Kilo Code ou les exigences de votre passerelle en amont au lieu de supposer que `User-Agent` est obligatoire pour BetterToken.
</Note>

## Vérifier la connexion

Envoyez une première requête courte, par exemple `Réponds uniquement : OK`. Si l’outil répond sans erreur d’authentification ou de Model ID, la connexion fonctionne. Redémarrez complètement l’outil après une modification. En cas d’échec, consultez les [erreurs courantes](#erreurs-courantes).

## Changer de modèle

Ouvrez le sélecteur de modèle ou modifiez le champ `Model` dans la configuration. Utilisez le Model ID exact du <a href={"{{model-plaza-url}}"}>model plaza</a>, puis redémarrez la session actuelle.

## Erreurs courantes

| Erreur | Vérifications |
| --- | --- |
| `401` ou `Unauthorized` | Vérifiez la BetterToken API Key et supprimez les espaces initiaux ou finaux. |
| `404` | Vérifiez la Base URL et n’ajoutez pas de chemin d’endpoint spécifique. |
| `model not found` | Copiez un Model ID actuel depuis le model plaza. |
| Les modifications ne sont pas appliquées | Enregistrez la configuration et redémarrez complètement l’outil. |
