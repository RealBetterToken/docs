« Grok CLI » peut désigner deux outils différents :

- **Grok Build**, le coding agent officiel de xAI ;
- **Community Grok CLI**, un projet open source sans affiliation avec xAI.

Les deux clients ont été vérifiés avec BetterToken : chacun a renvoyé une réponse du modèle avec une API Key BetterToken, une Base URL et un Model ID. Ce guide commence par **Community Grok CLI**, plus direct à configurer.

<Warning>Les deux outils utilisent la commande `grok`. S’ils sont installés ensemble, le terminal lance la première version trouvée dans `PATH`.</Warning>

## Différences entre Grok CLI et Grok Build

| Élément | Grok Build officiel | Community Grok CLI |
| --- | --- | --- |
| Mainteneur | xAI | `superagent-ai/grok-cli`, sans affiliation avec xAI |
| Authentification | Connexion par navigateur ou `XAI_API_KEY` | `GROK_API_KEY` |
| Base URL personnalisée | Dans `~/.grok/config.toml` | Avec `GROK_BASE_URL` |
| Modèle | Alias dans la configuration | `GROK_MODEL` |
| Appel de modèles via BetterToken | Vérifié | Vérifié |
| Commande | `grok` | `grok` |

La vérification couvre les requêtes de modèles de texte et de code, pas les appels d’outils ni les API propres à xAI.

## Utiliser Community Grok CLI avec BetterToken

Ces commandes s’appliquent à macOS, Linux et WSL. L’installation Windows native du client communautaire n’a pas été vérifiée.

### Installation

```bash
curl -fsSL https://raw.githubusercontent.com/superagent-ai/grok-cli/main/install.sh | bash
grok --version
```

Si Bun est déjà installé :

```bash
bun add -g grok-dev
```

### Configurer BetterToken

```bash
export GROK_BASE_URL="{{openai-base-url}}"
export GROK_API_KEY="YOUR_API_KEY"
export GROK_MODEL="YOUR_MODEL_ID"
```

Remplacez `YOUR_MODEL_ID` par le Model ID complet du <a href={"{{model-plaza-url}}"}>model plaza</a> et utilisez votre <a href={"{{register-url}}"}>API Key BetterToken</a>.

### Vérifier la connexion

```bash
grok -p "Reply with only: OK"
```

Seule une réponse du modèle confirme le fonctionnement de l’API Key, de la Base URL et du Model ID. Redémarrez le client après avoir modifié les variables d’environnement.

## Grok Build officiel

[Grok Build](https://docs.x.ai/build/overview) est le coding agent officiel de xAI pour le terminal.

### Installation et authentification

<Tabs>
  <Tab title="macOS / Linux / WSL">
    ```bash
    curl -fsSL https://x.ai/cli/install.sh | bash
    grok --version
    ```
  </Tab>
  <Tab title="Windows PowerShell">
    ```powershell
    irm https://x.ai/cli/install.ps1 | iex
    grok --version
    ```
  </Tab>
</Tabs>

Au premier lancement, Grok Build ouvre le navigateur. Sans navigateur :

```bash
export XAI_API_KEY="YOUR_XAI_API_KEY"
grok
```

### Configurer BetterToken dans Grok Build

```toml
[model.bettertoken]
model = "YOUR_MODEL_ID"
base_url = "{{openai-base-url}}"
name = "BetterToken"
env_key = "BETTERTOKEN_API_KEY"
api_backend = "chat_completions"

[models]
default = "bettertoken"
```

`BETTERTOKEN_API_KEY` est un nom choisi pour l’exemple. Grok Build lit la variable indiquée par `env_key`.

```bash
export BETTERTOKEN_API_KEY="YOUR_API_KEY"
grok inspect
grok -p "Reply with only: OK" -m bettertoken
```

<Note>Grok Build a renvoyé une réponse du modèle via BetterToken avec cette configuration. Cela ne vérifie pas les appels d’outils ni les API propres à xAI.</Note>

## Erreurs fréquentes

| Problème | Vérification |
| --- | --- |
| Le mauvais client démarre | Vérifiez le chemin et la version de chaque commande `grok`. |
| `401` ou `Unauthorized` | Community CLI lit `GROK_API_KEY` ; Grok Build lit la variable définie dans `env_key`. |
| `model not found` | Copiez le Model ID complet du model plaza, puis redémarrez. |
| La requête part encore vers xAI | Vérifiez `GROK_BASE_URL` ou exécutez `grok inspect` dans Grok Build. |

## Modèles et limites fonctionnelles

Utilisez un Model ID complet compatible OpenAI depuis le <a href={"{{model-plaza-url}}"}>model plaza</a>. X Search, la voix, les images, la vidéo et les autres API propres à xAI ne font pas partie de cette configuration.
