## 短い答え

Cursor Rules は、プロジェクト内での作業方法を Cursor に伝えます。`AGENTS.md` は多くのコーディングエージェントが読み取れるリポジトリ指示ファイルです。`.cursorignore` は、Cursor がインデックスまたは読み取りを行わないファイルやディレクトリを制御します。

いずれもプロジェクトコンテキストに関係しますが、解決する問題は異なります。Rules は動作を導き、`AGENTS.md` はエージェント横断の指示を与え、`.cursorignore` はコンテンツを除外します。

## 比較

| ファイル / 機能 | 主な役割 |
| --- | --- |
| Cursor Rules | Cursor 向けのプロジェクト、チーム、またはユーザーレベルのルール |
| `AGENTS.md` | エージェント横断のリポジトリ指示と共同作業の規範 |
| `.cursorignore` | Cursor が無視すべきファイルまたはディレクトリ |
| API Key / Base URL | モデルリクエストの設定。プロジェクトルールではありません |

## Rules に適した内容

- プロジェクトのコーディングスタイル
- フレームワークの規約
- コンポーネントとディレクトリのルール
- テストと検証の要件
- Cursor の編集動作

## .cursorignore に適した内容

- 大きなビルド成果物
- 依存関係ディレクトリ
- 生成ファイル
- インデックスすべきでない機密ディレクトリ
- 現在の開発に関係のない大きなファイル

## よくある間違い

- Rules または `AGENTS.md` に API Key を書き込むこと。
- `.cursorignore` を完全なセキュリティシステムとして扱うこと。
- AI を誤導する古いルールを残すこと。
- Base URL 設定がプロジェクトルールを置き換えると考えること。
- Cursor Rules と Claude Code の `CLAUDE.md` を混同すること。

## BetterToken について

BetterToken はモデル API アクセスと使用状況の可視化を扱います。Cursor Rules、`AGENTS.md`、`.cursorignore` はプロジェクトコンテキストと編集動作を扱います。

API アクセスは最初の一歩にすぎません。長期的な出力品質は、明確なルールと制御されたコンテキストに大きく依存します。
