Установка Hermes Agent включает установщик проекта и настройку OpenAI-compatible provider. Укажите API Key BetterToken, Base URL `{{openai-base-url}}` и точный Model ID.

## Hermes Agent: установка и API timeout

Если Hermes Agent завершает запрос по timeout, сначала проверьте короткий запрос без инструментов и уменьшите объём контекста. Сравните конфигурацию с [OpenClaw](/ai-tools/openclaw) и [Codex CLI](/ai-tools/codex), а адрес проверьте по [руководству по Base URL](/faq/model-calling/base-url-config).

## Ключевые параметры

| Поле | Значение |
| --- | --- |
| API Key | API Key BetterToken |
| Base URL | `{{openai-base-url}}` |
| Model | Актуальный Model ID из <a href={"{{model-plaza-url}}"}>каталога моделей</a> |

## Подготовка

- Установленная актуальная версия инструмента
- API Key BetterToken: <a href={"{{register-url}}"}>зарегистрироваться и получить</a>
- Model ID из <a href={"{{model-plaza-url}}"}>каталога моделей</a>

### Дополнительные требования

- выбранный Model ID доступен у провайдера **GPT**
- macOS, Linux, Windows 10/11 или WSL2
- модель с контекстом не менее 64K для работы Hermes Agent с инструментами

## Установка

### Установка Hermes Agent

<Tabs>
  <Tab title="Desktop (macOS / Windows)">
    Hermes рекомендует установщик Desktop для macOS и Windows. [Скачайте Hermes Desktop](https://hermes-agent.nousresearch.com/) и запустите установщик для своей операционной системы.
  </Tab>

  <Tab title="Linux / macOS / WSL2">
    ```bash
    curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
    ```

    После установки откройте новый терминал или перезагрузите shell, прежде чем запускать `hermes`.
  </Tab>

  <Tab title="Windows PowerShell">
    Hermes Agent нативно поддерживает Windows 10 и Windows 11. Откройте PowerShell или Windows Terminal и выполните:

    ```powershell
    iex (irm https://hermes-agent.nousresearch.com/install.ps1)
    ```

    Права администратора не нужны. После установки откройте новое окно PowerShell, чтобы обновленный User PATH стал доступен.
  </Tab>
</Tabs>

Проверьте установку:

```bash
hermes --version
hermes doctor
```

<Note>
  WSL2 по-прежнему поддерживается, но не является обязательным. Используйте его, если вам нужна Linux-среда или встроенная терминальная панель Web Dashboard.
</Note>

## Ручная настройка

Основной способ — интерактивный интерфейс настройки моделей Hermes Agent. Редактируйте файлы конфигурации напрямую только для ручной настройки.

| Поле | Значение |
| --- | --- |
| API Key | API Key BetterToken |
| Base URL | `{{openai-base-url}}` |
| Model | Актуальный Model ID из <a href={"{{model-plaza-url}}"}>каталога моделей</a> |

### Настройка

<Tabs>
  <Tab title="Интерактивная настройка">
    <Steps>
      <Step title="Запустите выбор модели">
        Сначала завершите активный чат Hermes, затем выполните:

        ```bash
        hermes model
        ```
      </Step>

      <Step title="Выберите Custom endpoint">
        В списке providers выберите **Custom endpoint (self-hosted / VLLM / etc.)**.
      </Step>

      <Step title="Заполните конфигурацию BetterToken">
        Введите:

        - **Base URL**: `{{openai-base-url}}`
        - **API Key**: ваш API Key BetterToken
        - **Model**: Model ID провайдера **GPT** из <a href={"{{model-plaza-url}}"}>model plaza</a>

        Если Hermes запрашивает API mode, выберите вариант OpenAI-compatible Chat Completions. Если нужно указать context length, используйте опубликованное значение модели не ниже 64K.
      </Step>

      <Step title="Запустите Hermes Agent">
        ```bash
        hermes --tui
        ```

        Для классического терминального интерфейса можно выполнить `hermes`.
      </Step>
    </Steps>
  </Tab>

  <Tab title="Файлы конфигурации">
    Интерактивная настройка безопаснее: она проверяет и сохраняет endpoint. Для ручной настройки добавьте несекретные параметры модели в `~/.hermes/config.yaml`:

    ```yaml
    model:
      default: YOUR_MODEL_ID
      provider: custom
      base_url: "{{openai-base-url}}"
    ```

    API Key храните отдельно в `~/.hermes/.env`:

    ```dotenv
    OPENAI_API_KEY=YOUR_API_KEY
    ```

    В native Windows эти файлы находятся в `%LOCALAPPDATA%\hermes\`, а не в `~/.hermes/`. Замените `YOUR_MODEL_ID` и `YOUR_API_KEY`, затем выполните `hermes doctor` перед запуском Hermes.
  </Tab>
</Tabs>

### Кратко о возможностях

| Возможность | Для чего нужна |
| --- | --- |
| Terminal UI | Общение с agent прямо в терминале |
| Skills | Сохранение повторяемых workflows |
| MCP | Подключение локальных или удаленных инструментов |
| Scheduled tasks | Запуск задач по расписанию и recurring workflows |
| Subagents | Разделение сложной работы между специализированными agents |
| Message gateway | Подключение agent к дополнительным message entry points |

### Troubleshooting

- Если запросы не отвечают или завершаются ошибкой, проверьте, что **Base URL** равен `{{openai-base-url}}`. Обычно здесь не нужно добавлять `/chat/completions`.
- Если Hermes сообщает, что модель не существует, проверьте, что **Model** — это Model ID поддерживаемого провайдера из <a href={"{{model-plaza-url}}"}>model plaza</a>.
- Если возникает ошибка авторизации, проверьте лишние пробелы в API Key и убедитесь, что Model ID доступен у провайдера **GPT**.
- Если Hermes все еще использует старую модель, завершите чат, снова сохраните custom endpoint через `hermes model` и начните новый чат.
- BetterToken обычно не требует дополнительного `User-Agent` или custom headers. Добавляйте headers только если этого явно требует ваш custom gateway, tenant routing, observability или caching layer.

<Note>
  Не коммитьте реальные API Keys в репозиторий. Для командных конфигураций используйте environment variables или локальную конфигурацию.
</Note>

## Проверка подключения

Запустите `hermes --tui` или `hermes`, затем отправьте короткий запрос:

```text
Reply with HERMES_OK only. Do not use tools.
```

Подключение работает, если Hermes возвращает `HERMES_OK` без ошибок авторизации, endpoint или Model ID. После этого выполните одну небольшую задачу только на чтение, прежде чем включать gateways, scheduled tasks или дополнительные инструменты.

## Смена модели

Для добавления или повторной настройки provider выполните `hermes model` вне чата. В активном чате используйте `/model` для переключения между уже настроенными providers и моделями. Используйте точный Model ID из <a href={"{{model-plaza-url}}"}>каталога моделей</a>.

## Частые ошибки

| Ошибка | Что проверить |
| --- | --- |
| `API timeout` | Проверьте короткий запрос без инструментов, уменьшите контекст и увеличьте timeout в конфигурации Hermes Agent. |
| `connection error` | Проверьте Base URL `{{openai-base-url}}`, DNS и конфликтующий прокси. |
| `401` или `403` | Повторно задайте API Key BetterToken и проверьте доступ к выбранной модели. |
| `429` | Проверьте доступность модели и состояние баланса, затем повторите один запрос. |
| `hermes: command not found` | После установки откройте новый терминал и проверьте PATH. |
| Ошибка конфигурации после обновления | Выполните `hermes config check`, затем `hermes config migrate`, если Hermes предложит миграцию. |

## Технические детали

<Accordion title="Протокол, endpoint и внутренние параметры provider">
  В описанном сценарии используется Base URL `{{openai-base-url}}`. Инструмент сам добавляет путь OpenAI-compatible endpoint. Не добавляйте `/chat/completions` или `/responses` к Base URL, если это не требуется конкретным полем.

### Миграция с OpenClaw

Если вы уже используете OpenClaw, сначала проверьте, есть ли в вашей текущей версии Hermes Agent команда миграции. Перед изменениями запустите dry run.

```bash
hermes claw migrate --dry-run
```

После проверки результата выполните миграцию:

```bash
hermes claw migrate
```

После миграции все равно проверьте **Base URL**, API Key и model ID в Hermes Agent. Они должны соответствовать `{{openai-base-url}}`, вашему API Key BetterToken и Model ID поддерживаемого провайдера.
</Accordion>
