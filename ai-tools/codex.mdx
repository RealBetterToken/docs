Codex Desktop и Codex CLI подключаются к BetterToken third-party API по OpenAI Responses. Конфигурация находится в `~/.codex/config.toml`, а API-ключ Codex передаётся через `BETTERTOKEN_API_KEY`.

## Codex Desktop third-party API и API-ключ

Для подключения задайте `model_provider = "custom"`, Base URL `{{openai-base-url}}` и `wire_api = "responses"`. Полную схему файла смотрите в [руководстве по config.toml](/faq/codex/config-toml). Для VS Code используется [отдельная конфигурация Codex Extension](/ai-tools/codex-vscode), а значения provider объясняет [справка по model_provider и wire_api](/faq/codex/model-provider-base-url-wire-api).

## Ключевые параметры

| Поле | Значение |
| --- | --- |
| API Key | Переменная окружения `BETTERTOKEN_API_KEY` |
| Base URL | `{{openai-base-url}}` |
| Model | `YOUR_MODEL_ID` |

## Подготовка

- Установите Node.js
- <a href={"{{register-url}}"}>Создайте API Key BetterToken</a>
- Скопируйте Model ID из <a href={"{{model-plaza-url}}"}>model plaza</a> или окна **Setup** для ключа

## Установка

```bash
npm install -g @openai/codex
```

## Настройка командой

Скрипт Automatic setup от BetterToken записывает конфигурацию provider для Codex. Для него нужен Node.js; если API Key или Model ID не переданы параметрами, скрипт запросит их интерактивно.

<Tabs>
  <Tab title="macOS / Linux">
    ```bash
    curl -fsSL "{{install-codex-provider-sh-url}}" | bash
    ```
  </Tab>
  <Tab title="Windows">
    ```powershell
    iwr "{{install-codex-provider-ps1-url}}" -OutFile "$env:TEMP\install-codex-provider.ps1"; powershell -ExecutionPolicy Bypass -File "$env:TEMP\install-codex-provider.ps1"
    ```
  </Tab>
</Tabs>

После выполнения откройте `~/.codex/config.toml` (в Windows — `%USERPROFILE%\.codex\config.toml`), проверьте значения `model`, `review_model` и provider BetterToken, затем полностью перезапустите Codex.

## Ручная настройка

GPT, Kimi и GLM используют одну структуру `config.toml`. Замените только `YOUR_MODEL_ID` на актуальный Model ID выбранного провайдера. Настройка одной командой сейчас доступна только для GPT.

### Настройка API Key

<Tabs>
  <Tab title="macOS / Linux">
    ```bash
    export BETTERTOKEN_API_KEY="YOUR_API_KEY"
    ```

    Для постоянного значения добавьте строку в `~/.zshrc` или `~/.bashrc`.
  </Tab>
  <Tab title="Windows PowerShell">
    ```powershell
    [Environment]::SetEnvironmentVariable("BETTERTOKEN_API_KEY", "YOUR_API_KEY", "User")
    $env:BETTERTOKEN_API_KEY = "YOUR_API_KEY"
    ```
  </Tab>
</Tabs>

<Warning>
  Не записывайте API Key BetterToken в `~/.codex/auth.json`. Этот файл нужен для официального входа Codex; custom provider должен читать переменную через `env_key`.
</Warning>

### Настройка config.toml

Отредактируйте `~/.codex/config.toml`:

```toml
model_provider = "custom"
model = "YOUR_MODEL_ID"
review_model = "YOUR_MODEL_ID"
model_reasoning_effort = "high"

[model_providers.custom]
name = "BetterToken"
base_url = "{{openai-base-url}}"
env_key = "BETTERTOKEN_API_KEY"
wire_api = "responses"
requires_openai_auth = false
request_max_retries = 4
stream_max_retries = 8
stream_idle_timeout_ms = 300000
supports_websockets = false
```

`model_provider = "custom"` должен совпадать с `[model_providers.custom]`. Замените оба `YOUR_MODEL_ID` на актуальный полный Model ID.

## Проверка подключения

Откройте новый терминал и выполните:

```bash
codex
```

Отправьте короткую задачу. Потоковый ответ без ошибок входа, `401` или модели подтверждает настройку.

## Смена модели

Измените `model` и при необходимости `review_model`, сохраните файл и полностью перезапустите Codex. Используйте ID из окна Setup или model plaza.

## Частые ошибки

| Ошибка | Решение |
| --- | --- |
| `401` или запрос входа OpenAI | Проверьте `BETTERTOKEN_API_KEY` и `requires_openai_auth = false`. |
| `403` | Проверьте, экспортирована ли `BETTERTOKEN_API_KEY` в том же окружении, где запущен Codex, и доступна ли выбранная модель. |
| `timeout` или поток прерван | Проверьте `stream_idle_timeout_ms`, затем повторите короткий запрос без лишнего контекста. |
| Provider не найден | Значение `model_provider = "custom"` должно совпадать с `[model_providers.custom]`. |
| Ошибка API mode | Сохраните `wire_api = "responses"`; не переходите на Chat Completions. |
| Модель не найдена | Замените `YOUR_MODEL_ID` на актуальный полный ID из Setup или model plaza. |
| Конфигурация не применилась | Откройте новый терминал, проверьте переменную и полностью перезапустите Codex. |

### Поддерживаемые провайдеры

| Провайдер | Статус |
| --- | --- |
| Claude | Не поддерживается |
| GPT | Настройка командой + вручную |
| Kimi | Ручная настройка |
| GLM | Ручная настройка |

<Note>Статусы относятся к способу подключения BetterToken, описанному на этой странице.</Note>

<Accordion title="Что означают способы настройки">
  - **Настройка командой + вручную**: доступна готовая команда и полная ручная настройка.
  - **Ручная настройка**: укажите API Key, Base URL и Model.
  - **Не поддерживается**: проверенный способ прямого подключения пока отсутствует.
</Accordion>

### Codex Extension

Расширение Codex для VS Code использует тот же `config.toml`, но для сохранения официального входа нужна другая схема авторизации. См. [настройку Codex Extension](/ai-tools/codex-vscode).

<Warning>
  Конфигурация CLI/App и конфигурация Extension с официальным входом — альтернативы. Не вставляйте два table `[model_providers.custom]` в один TOML-файл.
</Warning>
