Чтобы подключить Dify к OpenAI API-compatible endpoint BetterToken, установите плагин модели, укажите Base URL `{{openai-base-url}}`, API Key и точный Model ID.

## Dify OpenAI API-compatible timeout

При timeout сначала проверьте обычный чат без Agent tools, затем увеличьте timeout в настройках Dify и повторите короткий запрос. Сравните интеграцию с [n8n](/ai-tools/n8n), проверьте [правильный Base URL](/faq/model-calling/base-url-config) и выберите модель по [руководству](/faq/model-calling/model-selection-guide).

## Ключевые параметры

| Поле | Значение |
| --- | --- |
| API Key | API Key BetterToken |
| Base URL | `{{openai-base-url}}` |
| Model | Актуальный Model ID из <a href={"{{model-plaza-url}}"}>каталога моделей</a> |

## Подготовка

- Установленная актуальная версия инструмента
- API Key BetterToken: <a href={"{{register-url}}"}>зарегистрироваться и получить</a>
- Model ID из <a href={"{{model-plaza-url}}"}>каталога моделей</a>

## Установка

### Установка OpenAI-compatible model plugin

<Steps>
  <Step title="Откройте Model Providers">
    В workspace Dify перейдите в **Integrations > Model Providers**.
  </Step>

  <Step title="Установите официальный плагин">
    Нажмите **Install model providers**, найдите **OpenAI-API-compatible** и установите его.

    Dify управляет model providers как плагинами уровня workspace. После установки приложения с нужными правами смогут выбирать модели этого provider.
  </Step>

  <Step title="Добавьте custom model">
    На карточке **OpenAI-API-compatible** нажмите **Add Model**. Если сначала отображается **Setup** или **Configure**, откройте этот раздел и выберите добавление модели.
  </Step>
</Steps>

## Ручная настройка

Выполните эту настройку в интерфейсе провайдеров моделей Dify. Редактировать конфигурационный файл вручную не требуется.

| Поле | Значение |
| --- | --- |
| API Key | API Key BetterToken |
| Base URL | `{{openai-base-url}}` |
| Model | Актуальный Model ID из <a href={"{{model-plaza-url}}"}>каталога моделей</a> |

### Что потребуется

- Dify Cloud или собственный экземпляр Dify с включёнными плагинами
- API Key BetterToken (<a href={"{{register-url}}"}>зарегистрироваться</a>)
- Model ID провайдера **GPT** из <a href={"{{model-plaza-url}}"}>model plaza</a>
- Права на установку model plugins и управление моделями workspace

<Note>
  Инструкция относится только к **LLM Chat**. Не добавляйте GPT chat model как Text Embedding, Rerank, Speech-to-Text или Text-to-Speech.
</Note>

### Конфигурация модели

Для первой модели заполните поля так:

| Поле Dify | Рекомендуемое значение |
|---|---|
| Model Type | `LLM` |
| Model Name | Model ID поддерживаемого провайдера из model plaza |
| Model display name | можно повторить Model Name |
| API Key | API Key BetterToken |
| API Base URL | `{{openai-base-url}}` |
| model name for API endpoint | тот же ID, что и в Model Name |
| Completion mode | `Chat` |
| Model context size | по возможностям модели; если не уверены, оставьте значение плагина |
| Upper bound for max tokens | не выше лимита модели; для первого теста оставьте значение плагина |
| Compatibility mode | `OpenAI compatible` / strict |
| Token parameter name | `Auto` |
| Function Call Type | `Not Support` для первого теста |

<Warning>
  В API Base URL укажите только `{{openai-base-url}}`. Не добавляйте `/chat/completions`: плагин Dify сам вызывает нужный endpoint.
</Warning>

Для остальных возможностей сначала выберите консервативные значения:

- **Thinking Mode Support**: включайте только после проверки поддержки моделью
- **Stream function calling**: для первого теста выберите `Not Support`
- **Vision Support**: включайте, только если модель и endpoint принимают изображения
- **Structured Output**: сначала выключите и проверьте обычный чат

Нажмите **Save**. Dify проверит API Key, Base URL и ID модели.

### Использование модели в приложении

<Steps>
  <Step title="Создайте или откройте приложение Dify">
    Откройте Chatbot, Agent, Chatflow или Workflow.
  </Step>

  <Step title="Выберите модель">
    В model selector приложения или в узле **LLM** выберите модель, добавленную в **OpenAI-API-compatible**.
  </Step>

  <Step title="Сначала проверьте обычный чат">
    Выполните первый запрос с коротким текстом, без инструментов и изображений:

    ```text
    Ответь только: Подключение работает
    ```
  </Step>

  <Step title="Затем включите возможности Agent">
    Когда обычный чат заработает, при необходимости измените конфигурацию модели. Укажите в **Function Call Type** режим, который поддерживает модель. В OpenAI-compatible API обычно используется `Tool Call`, но поддержку нужно проверять для выбранных модели и endpoint.
  </Step>
</Steps>

### Решение проблем

### При сохранении возвращается 401

- Проверьте API Key
- Убедитесь, что Model ID доступен у провайдера **GPT**
- Проверьте статус ключа и баланс в Dashboard BetterToken

### При сохранении возвращается 404

- API Base URL должен быть `{{openai-base-url}}`
- Не добавляйте `/chat/completions`
- Проверьте, что **model name for API endpoint** полностью совпадает с ID в model plaza

### Dify сообщает model not found

**Model Name** влияет на отображение и выбор модели в Dify. В запрос отправляется значение **model name for API endpoint**. Укажите в обоих полях один и тот же Model ID поддерживаемого провайдера.

### Обычный чат работает, а инструменты Agent — нет

Верните **Function Call Type** в `Not Support` и проверьте базовый узел LLM. Выбирайте `Tool Call`, только если модель поддерживает вызов инструментов, а затем повторно проверьте их параметры.

### Knowledge не позволяет выбрать эту модель как Embedding Model

Это ожидаемо: chat LLM не заменяет embedding model. Инструкция не подтверждает наличие у BetterToken embedding или rerank endpoints для Dify. Подключите для Knowledge отдельный поддерживаемый embedding provider.

## Проверка подключения

Отправьте короткий тестовый запрос. Если инструмент возвращает ответ без ошибок авторизации или Model ID, подключение работает. После изменения конфигурации полностью перезапустите инструмент.

## Смена модели

Откройте селектор моделей или измените поле `Model` в конфигурации. Используйте точный Model ID из <a href={"{{model-plaza-url}}"}>каталога моделей</a>, затем перезапустите текущую сессию.

Dify хранит отдельную custom-конфигурацию для каждого model ID. Чтобы добавить ещё одну модель поддерживаемого провайдера, снова нажмите **Add Model** в том же provider. Укажите новый ID в **Model Name** и **model name for API endpoint**. Base URL и API Key можно использовать повторно.

## Частые ошибки

| Ошибка | Что проверить |
| --- | --- |
| `401` или `Unauthorized` | Проверьте API Key и удалите лишние пробелы. |
| `403` | Проверьте, доступен ли выбранный Model ID для API Key. |
| `timeout` | Сначала проверьте обычный чат без Agent tools, затем увеличьте timeout и повторите короткий запрос. |
| `404` | Проверьте Base URL и не добавляйте путь конкретного endpoint. |
| `model not found` | Скопируйте актуальный Model ID из каталога моделей. |
| Настройки не применились | Сохраните файл и полностью перезапустите инструмент. |
