Codex VS Code custom API использует общий с Codex CLI/App файл `~/.codex/config.toml`. API Key BetterToken можно передать через `experimental_bearer_token`, сохранив официальный вход, плагины и Remote Control.

## Codex VS Code custom API и API Key

Не вставляйте одновременно конфигурации CLI/App и Extension с одинаковым TOML table. Базовая настройка находится в [руководстве по Codex CLI/App](/ai-tools/codex), поля файла — в [FAQ по config.toml](/faq/codex/config-toml), а сохранение официальной авторизации — в [отдельной инструкции](/faq/codex/official-login-third-party-api).

## Ключевые параметры

| Поле | Значение |
| --- | --- |
| API Key | `experimental_bearer_token = "YOUR_API_KEY"` |
| Base URL | `{{openai-base-url}}` |
| Model | `YOUR_MODEL_ID` |

## Подготовка

- Установите последнюю версию Codex VS Code Extension
- Выполните официальный вход в Extension или Codex App
- <a href={"{{register-url}}"}>Создайте API Key BetterToken</a>
- Скопируйте Model ID из <a href={"{{model-plaza-url}}"}>model plaza</a> или окна **Setup** для ключа

## Установка

Установите расширение из Marketplace VS Code, затем перезапустите VS Code.

## Ручная настройка

### Настройка Extension

Отредактируйте `~/.codex/config.toml`:

```toml
model_provider = "custom"
model = "YOUR_MODEL_ID"
review_model = "YOUR_MODEL_ID"
model_reasoning_effort = "high"

[model_providers.custom]
name = "BetterToken"
base_url = "{{openai-base-url}}"
wire_api = "responses"
requires_openai_auth = true
experimental_bearer_token = "YOUR_API_KEY"
```

Сохраните файл, выполните **Developer: Reload Window** в VS Code и снова откройте панель Codex.

<Note>
  `requires_openai_auth = true` сохраняет официальный вход, а `experimental_bearer_token` используется для запросов к BetterToken. Не записывайте API Key BetterToken в `auth.json`.
</Note>

### Не смешивайте авторизацию CLI/App и Extension

| Сценарий | Поля авторизации |
| --- | --- |
| Только custom provider Codex CLI/App | `env_key = "BETTERTOKEN_API_KEY"` и `requires_openai_auth = false` |
| Extension с официальным входом | `requires_openai_auth = true` и `experimental_bearer_token = "YOUR_API_KEY"` |

Оба варианта используют `[model_providers.custom]`. В одном TOML-файле должен быть только один такой table.

## Проверка подключения

Создайте новую сессию Extension и отправьте короткую задачу. Ответ от `YOUR_MODEL_ID` при доступных плагинах и Remote Control подтверждает настройку.

## Смена модели

Измените `model` и при необходимости `review_model`, затем выполните **Developer: Reload Window**. Используйте Model ID из окна Setup или model plaza.

## Частые ошибки

| Ошибка | Решение |
| --- | --- |
| Extension снова просит вход | Восстановите официальный вход и сохраните `requires_openai_auth = true`. |
| `401` или `403` | Скопируйте `experimental_bearer_token` заново; не перезаписывайте `auth.json`. |
| Duplicate table | Удалите второй `[model_providers.custom]` и оставьте один режим авторизации. |
| Модель не найдена | Замените `YOUR_MODEL_ID` на актуальный полный ID. |
| Конфигурация не применилась | Сохраните файл и выполните **Developer: Reload Window**. |

## Технические детали

<Accordion title="Почему авторизация Extension отличается от CLI/App">
  Extension использует официальный вход для части функций Codex, поэтому здесь сохраняется `requires_openai_auth = true`. Для чистого custom provider CLI/App используется переменная окружения и `requires_openai_auth = false`. Оба варианта отправляют OpenAI Responses через `{{openai-base-url}}`.
</Accordion>
