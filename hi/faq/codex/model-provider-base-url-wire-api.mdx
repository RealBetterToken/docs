## संक्षिप्त उत्तर

`model_provider`, Codex CLI को बताता है कि कौन-सा provider उपयोग करना है। इसका value `[model_providers.<id>]` के अंतर्गत परिभाषित provider id से मेल खाना चाहिए।

`base_url` वह API endpoint है जहां model requests भेजे जाते हैं। OpenAI-compatible provider के लिए यह आमतौर पर `/v1` style endpoint की ओर संकेत करता है।

`wire_api`, Codex को उस provider से बात करते समय उपयोग करने के लिए protocol shape बताता है। Codex configuration reference में `responses`, supported provider protocol value है।

## यह कब महत्वपूर्ण है

- आप custom OpenAI-compatible provider कॉन्फ़िगर कर रहे हैं
- Codex कहता है कि provider नहीं मिला या model requests विफल होते हैं
- आपको नहीं पता कि `model_provider`, `model` से कैसे अलग है
- आप BetterToken, OpenAI या अन्य provider को एक `config.toml` में रख रहे हैं
- आपको Base URL, API Key और Model ID अलग रखने हैं

## Field संबंध

| Field | उद्देश्य |
| --- | --- |
| `model_provider` | सक्रिय provider id चुनता है |
| `[model_providers.<id>]` | एक provider का विस्तृत configuration परिभाषित करता है |
| `name` | provider का display name |
| `base_url` | root API endpoint |
| `wire_api` | provider protocol, आमतौर पर `responses` |
| `model` | default main model ID |
| `review_model` | `/review` जैसे code review flows के लिए उपयोग model |

## फ़ाइलें खोजें और बैकअप लें

यदि आपने अपना `CODEX_HOME` सेट किया है, तो उसी डायरेक्टरी में `config.toml` और `auth.json` संपादित करें। अन्यथा macOS / Linux पर `~/.codex` या Windows पर `%USERPROFILE%\.codex` उपयोग करें। CLI और App को एक ही डायरेक्टरी इस्तेमाल करनी चाहिए। WSL की उपयोगकर्ता डायरेक्टरी अलग होती है।

संपादन से पहले Codex पूरी तरह बंद करें। दोनों फ़ाइलों का बैकअप निजी स्थान पर रखें। जो फ़ाइल मौजूद नहीं है उसे बनाएँ। मौजूदा सेटिंग बदलें; कुंजियाँ या टेबल दोबारा न जोड़ें। असंबंधित सेटिंग बनाए रखें।

<Warning>
  यह सेटअप ChatGPT लॉगिन से API Key प्रमाणीकरण पर स्विच करता है। आधिकारिक खाते का एक्सेस बना नहीं रहता। `auth.json` और उसके बैकअप सुरक्षित रखें; उन्हें साझा या रिपॉज़िटरी में कमिट न करें।
</Warning>

## अनुशंसित pattern

### config.toml संपादित करें

`model_provider`, `model` और `cli_auth_credentials_store` को सभी TOML टेबल से पहले शीर्ष स्तर पर रखें, प्रोफ़ाइल के अंदर नहीं। चुने गए प्रदाता का ID उसकी टेबल के नाम से मेल खाना चाहिए। इस फ़ाइल-आधारित प्रमाणीकरण के लिए चुने गए प्रदाता से `env_key` और `experimental_bearer_token` हटाएँ।

```toml
model_provider = "bettertoken"
model = "gpt-6-astra"
cli_auth_credentials_store = "file"

[model_providers.bettertoken]
name = "BetterToken"
base_url = "{{openai-base-url}}"
wire_api = "responses"
requires_openai_auth = true
request_max_retries = 4
stream_max_retries = 8
stream_idle_timeout_ms = 300000
supports_websockets = false
```

इस उदाहरण में GPT-6 Astra (`gpt-6-astra`) उपयोग होता है। दूसरे मॉडल के लिए <a href={"{{model-plaza-url}}"}>मॉडल प्लाज़ा</a> से पूरा ID कॉपी करके `model` बदलें। GPT, Kimi और GLM एक ही फ़ाइल-आधारित प्रमाणीकरण संरचना इस्तेमाल करते हैं; स्वचालित सेटअप GPT के लिए उपलब्ध है।

### auth.json संपादित करें

`auth.json` और `config.toml` एक ही डायरेक्टरी में होते हैं। अगर `auth.json` नहीं है, तो उसी डायरेक्टरी में यह फ़ाइल बनाएँ। फ़ाइल की सामग्री के रूप में निम्न JSON लिखें, `YOUR_API_KEY` की जगह अपनी BetterToken API Key डालें और फ़ाइल सेव करें।

```json
{
  "auth_mode": "apikey",
  "OPENAI_API_KEY": "YOUR_API_KEY"
}
```

## पुनः शुरू करके जाँचें

दोनों फ़ाइलें सहेजें। टर्मिनल में नया Codex CLI सत्र सीधे शुरू करें:

```bash
codex
```

पृष्ठभूमि प्रक्रियाओं सहित Codex App पूरी तरह बंद करें। फिर खोलें और नया स्थानीय कार्य बनाएँ। अपने इस्तेमाल के हर क्लाइंट में छोटा प्रॉम्प्ट भेजें। सामान्य उत्तर उस क्लाइंट का कनेक्शन सत्यापित करता है।

## समस्या निवारण

`401`, `403` या लॉगिन अनुरोध आने पर सक्रिय डायरेक्टरी, `auth.json` की Key, `auth_mode = apikey`, `cli_auth_credentials_store = file` और `requires_openai_auth = true` जाँचें। प्रदाता या मॉडल की त्रुटि होने पर प्रदाता ID का मिलान, `{{openai-base-url}}`, `wire_api = responses` और मॉडल की उपलब्धता जाँचें। बदलाव लागू न हों तो कॉन्फ़िगरेशन ओवरराइड जाँचें और सुनिश्चित करें कि CLI और App एक ही `CODEX_HOME` इस्तेमाल कर रहे हैं।
