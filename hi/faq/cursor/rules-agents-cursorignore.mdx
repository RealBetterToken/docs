## संक्षिप्त उत्तर

Cursor Rules, Cursor को बताते हैं कि project में कैसे काम करना है। `AGENTS.md`, repository instruction file है जिसे कई coding agents पढ़ सकते हैं। `.cursorignore` नियंत्रित करता है कि Cursor को किन files या directories को index या read नहीं करना चाहिए।

तीनों project context से संबंधित हैं, लेकिन वे अलग समस्याएं हल करते हैं: Rules behavior को guide करते हैं, `AGENTS.md` cross-agent instructions देता है और `.cursorignore` content को exclude करता है।

## तुलना

| File / feature | मुख्य भूमिका |
| --- | --- |
| Cursor Rules | Cursor के लिए project, team या user-level rules |
| `AGENTS.md` | cross-agent repository instructions और collaboration norms |
| `.cursorignore` | वे files या directories जिन्हें Cursor को ignore करना चाहिए |
| API Key / Base URL | model request setup, project rules नहीं |

## Rules के लिए अच्छी सामग्री

- project coding style
- framework conventions
- component और directory rules
- test और validation requirements
- Cursor editing behavior

## .cursorignore के लिए अच्छी सामग्री

- बड़े build artifacts
- dependency directories
- generated files
- sensitive directories जिन्हें index नहीं करना चाहिए
- current development से असंबंधित बड़ी files

## सामान्य गलतियां

- Rules या `AGENTS.md` में API Keys लिखना।
- `.cursorignore` को complete security system मानना।
- AI को गुमराह करने वाले outdated rules बनाए रखना।
- सोचना कि Base URL configuration project rules को बदलता है।
- Cursor Rules को Claude Code `CLAUDE.md` के साथ मिलाना।

## BetterToken के बारे में

BetterToken model API access और usage visibility संभालता है। Cursor Rules, `AGENTS.md` और `.cursorignore`, project context और editing behavior संभालते हैं।

API access केवल पहला चरण है। long-term output quality काफी हद तक स्पष्ट rules और controlled context पर निर्भर करती है।
