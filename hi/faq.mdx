## सेटअप और configuration

<AccordionGroup>
  <Accordion title="BetterToken का base_url क्या है?">
    BetterToken protocol के अनुसार दो अलग Endpoint उपयोग करता है:

    | उपयोग का तरीका | Base URL |
    |----------|----------|
    | Claude Code / `ANTHROPIC_BASE_URL` | `{{anthropic-base-url}}` |
    | Codex / `OPENAI_BASE_URL` / बाहरी टूल | `{{openai-base-url}}` |

    हर टूल में एक ही address दोबारा उपयोग न करें।
  </Accordion>

  <Accordion title="क्या Claude Code में मॉडल बताना जरूरी है?">
    यह प्रदाता पर निर्भर करता है।

    **Claude प्रदाता** के साथ केवल `ANTHROPIC_BASE_URL` और `ANTHROPIC_AUTH_TOKEN` सेट करें। मॉडल variable की जरूरत **नहीं** है।

    **GPT प्रदाता** के साथ `ANTHROPIC_DEFAULT_HAIKU_MODEL`, `ANTHROPIC_DEFAULT_SONNET_MODEL` और `ANTHROPIC_DEFAULT_OPUS_MODEL` से Claude Code मॉडल mapping जोड़ें। <a href={"{{model-plaza-url}}"}>मॉडल प्लाज़ा</a> के मौजूदा **GPT प्रदाता** से मॉडल ID कॉपी करें।
  </Accordion>

  <Accordion title="क्या Codex में मॉडल बताना जरूरी है?">
    हां। <a href={"{{model-plaza-url}}"}>मॉडल प्लाज़ा</a> के **GPT प्रदाता** से कॉपी किया गया मॉडल ID भरें।

    अधिक जानकारी के लिए [Codex सेटअप गाइड](/hi/ai-tools/codex) देखें।
  </Accordion>

  <Accordion title="क्या Cursor जैसे अन्य टूल में मॉडल बताना जरूरी है?">
    हां। Cursor, Cline, Zed और OpenClaw जैसे बाहरी टूल **GPT प्रदाता** का उपयोग करते हैं। <a href={"{{model-plaza-url}}"}>मॉडल प्लाज़ा</a> से मौजूदा मॉडल ID कॉपी करें।

    इन टूल में hardcoded Claude मॉडल नाम उपयोग न करें।

    अधिक जानकारी के लिए [Cursor सेटअप गाइड](/hi/ai-tools/cursor) देखें।
  </Accordion>

  <Accordion title="क्या OpenClaw और अन्य बाहरी टूल को अतिरिक्त header चाहिए?">
    आमतौर पर नहीं।

    जांचे गए official दस्तावेज़ों के अनुसार Cursor, Cline और Zed जैसे बाहरी टूल में `Base URL`, API Key और मॉडल ID मुख्य सेटिंग हैं। OpenCode और OpenClaw वैकल्पिक `headers` का समर्थन करते हैं, लेकिन official दस्तावेज़ इन्हें custom header या custom auth जरूरत बताते हैं, BetterToken का अनिवार्य सेटअप नहीं।

    अतिरिक्त header तभी जोड़ें जब टूल के official दस्तावेज़ या आपका upstream gateway, tenant routing, observability या Cache layer इसे स्पष्ट रूप से मांगे।
  </Accordion>

  <Accordion title="सेटअप के बाद authentication विफल हो तो क्या करें?">
    ये जांचें:

    1. API Key सही हो और उसमें अतिरिक्त space न हो।
    2. पुष्टि करें कि Claude Code `{{anthropic-base-url}}` और Codex / बाहरी टूल `{{openai-base-url}}` उपयोग करते हैं।
    3. जांचें कि पुराने `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_BASE_URL`, `OPENAI_API_KEY` या `OPENAI_BASE_URL` variable config को override तो नहीं कर रहे।
    4. बाहरी टूल के version limit, मॉडल allowlist या upstream gateway द्वारा मांगे गए अतिरिक्त header जैसी official जरूरतें जांचें।

    समस्या बनी रहे तो support से संपर्क करें।
  </Accordion>
</AccordionGroup>

## विश्वसनीयता और Rate Limit

<AccordionGroup>
  <Accordion title="BetterToken विश्वसनीयता कैसे बनाए रखता है?">
    BetterToken कई प्रदाताओं से कनेक्ट होता है और ये तरीके उपयोग करता है:

    - **कई स्रोत**: एक प्रदाता के outage से सभी Request बंद नहीं होते
    - **Dynamic routing**: BetterToken real time में सबसे तेज और स्थिर रास्ता चुनता है
    - **मुख्य टूल पर ध्यान**: Claude Code और Codex ecosystem की विश्वसनीयता को प्राथमिकता मिलती है
  </Accordion>

  <Accordion title="Rate Limit या timeout आए तो क्या करें?">
    BetterToken अलग-अलग प्रदाताओं के Rate Limit और timeout अपने-आप संभालता है। समस्या बनी रहे तो:

    1. जांचें कि बैलेंस पर्याप्त है।
    2. टूल का timeout बढ़ाएं (`API_TIMEOUT_MS=3000000` अनुशंसित है)।
    3. मौजूदा quota status के लिए support से संपर्क करें।
  </Accordion>

  <Accordion title="क्या BetterToken production के लिए उपयुक्त है?">
    BetterToken मुख्य रूप से Claude Code और Codex जैसे AI कोडिंग टूल इस्तेमाल करने वाले individual developer के लिए बनाया गया है। बड़े production API workload के लिए अपनी जरूरतों के अनुसार इसका मूल्यांकन करें।
  </Accordion>
</AccordionGroup>
