## 简短答案

Claude Code 可以通过多种方式认证。个人用户常见的是使用 Claude.ai 账号登录；团队或 API 用户也可能通过 Claude Console、云 provider，或支持的第三方 provider 方式接入。

Claude.ai 账号和 API Key 不是同一个东西。Claude.ai 登录用于官方账号和订阅体验；API Key 用于模型 API 请求，通常会和 Base URL、provider 配置一起使用。

如果你使用第三方 API gateway，核心配置通常是 API Key + Base URL。你需要确认当前工具支持的协议是 Anthropic-compatible 还是 OpenAI-compatible。

## 什么时候需要理解它

- 第一次启动 Claude Code，看到登录提示
- 不确定 Claude Pro / Max 是否等于 API Key
- 想把 Claude Code 请求路由到自定义 API gateway
- 需要在官方登录态和第三方 API provider 之间做取舍
- 团队需要统一管理 Claude Code 的认证方式

## 核心概念

| 概念 | 说明 |
| --- | --- |
| Claude.ai 账号 | 面向 Claude 产品体验的官方账号登录 |
| Claude Console API | Anthropic API 的开发者侧认证和用量管理 |
| API Key | 用于模型 API 请求的密钥，不等同于网页登录态 |
| Base URL | 请求发送到哪个 API endpoint |
| Provider | Claude Code 当前使用的认证和模型请求来源 |
| 第三方 API gateway | 在工具和模型供应之间提供兼容协议、路由和用量管理的一层 |

## 推荐判断方式

先问自己要解决什么问题：

1. 如果你只想使用官方 Claude Code，并且已经有 Claude.ai 订阅，优先使用官方登录。
2. 如果你要按 API 用量计费或由团队集中管理，查看 Claude Console 或团队认证方案。
3. 如果你要接入自定义 API gateway，确认 Claude Code 当前入口是否支持第三方 provider，并使用对应的 API Key 和 Base URL。
4. 如果你还需要插件、Remote Control 或官方会话同步，先确认是否需要保留官方登录态，再配置第三方推理层。

在本仓库的 Claude Code 接入文档中，Claude Code 的 Anthropic-compatible Base URL 是 `{{anthropic-base-url}}`。

## 常见误区

- 把 Claude.ai 订阅当作 API Key。订阅可以让你使用官方产品，但不自动变成第三方 API Key。
- 把 ChatGPT Plus 或其他产品订阅填进 Claude Code。
- 只复制 API Key，不配置 Base URL，导致请求仍然走默认官方 endpoint。
- 把 OpenAI-compatible Base URL 填进 Claude Code 的 Anthropic-compatible 配置。
- 把 `auth.json`、refresh token 或网页登录态发给别人。它们不是可共享 API Key。

## 关于 BetterToken

如果你选择 API Key + Base URL 路径，BetterToken 可以作为 API gateway 提供对应 endpoint，并在 dashboard 中集中展示 API Key、余额和用量记录。

BetterToken 不替代 Claude.ai 官方登录。它也不会把 Claude.ai 订阅转换成 API Key。它只处理模型 API 请求这一层。
