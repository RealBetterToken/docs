## 简短答案

Cursor Rules 用来告诉 Cursor 在项目中如何工作。`AGENTS.md` 是许多 coding agent 都能读取的项目说明文件。`.cursorignore` 用来控制 Cursor 不应索引或读取的内容范围。

它们都和项目上下文有关，但解决的问题不同：Rules 管行为，`AGENTS.md` 管跨工具说明，`.cursorignore` 管排除范围。

## 对比表

| 文件 / 功能 | 主要作用 |
| --- | --- |
| Cursor Rules | 给 Cursor 的项目、团队或用户级规则 |
| `AGENTS.md` | 跨 agent 的仓库说明和协作约定 |
| `.cursorignore` | 控制 Cursor 忽略哪些文件或目录 |
| API Key / Base URL | 模型请求配置，不负责项目规则 |

## 适合写进 Rules 的内容

- 项目代码风格
- 框架约定
- 组件和目录规范
- 测试和验证要求
- Cursor 在编辑时需要遵守的行为

## 适合写进 .cursorignore 的内容

- 大型构建产物
- 依赖目录
- 生成文件
- 不希望被索引的敏感目录
- 与当前开发无关的大文件

## 常见误区

- 把 API Key 写进 Rules 或 `AGENTS.md`。
- 以为 `.cursorignore` 是安全权限系统。
- 写很多过期规则，导致 AI 遵循错误上下文。
- 以为配置 Base URL 后就不需要项目规则。
- 混用 Cursor Rules 和 Claude Code 的 `CLAUDE.md`。

## 关于 BetterToken

BetterToken 解决模型 API 接入和用量观察。Cursor Rules、`AGENTS.md` 和 `.cursorignore` 解决项目上下文和编辑行为。

API 接通只是第一步。长期效果通常更依赖规则文件是否清晰、是否控制了无关上下文。
