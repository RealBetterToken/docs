## Короткий ответ

Для custom OpenAI-compatible API в Cursor держите согласованными три поля: API Key, Base URL и Model ID.

API Key авторизует запрос. Base URL определяет provider, куда уходит запрос. Model ID определяет модель. Все три значения должны относиться к одному provider или compatible gateway.

## Когда это важно

- Вы хотите использовать third-party OpenAI-compatible provider в Cursor
- Нужно задать Override OpenAI Base URL
- Вы добавляете custom model
- Видите model not found или authentication failures
- Хотите, чтобы Cursor, Codex и другие tools использовали один model routing layer

## Значение полей

| Поле | Роль |
| --- | --- |
| API Key | Authentication credential |
| Base URL | OpenAI-compatible endpoint, обычно `/v1` URL |
| Model ID | Model identifier, который распознает provider |
| Custom model | Модель, вручную добавленная или выбранная в Cursor |

## Рекомендуемые шаги

1. Создайте API Key в provider dashboard.
2. Добавьте API Key в Cursor model settings.
3. Введите provider Base URL в Override OpenAI Base URL.
4. Добавьте или выберите Model ID, который поддерживает provider.
5. Сохраните и проверьте простым запросом.

## Частые ошибки

- API Key от одного provider, а Base URL от другого.
- Claude model name в OpenAI-compatible configuration.
- UI display name вместо API model ID.
- Думать, что Cursor Rules влияют на API authentication.
- Забывать, что global override может влиять на другие OpenAI models.

## О LLMEasy

Cursor и похожие external tools обычно используют OpenAI-compatible setup. Base URL LLMEasy — `{{openai-base-url}}`, а model IDs берутся из **группы ключа GPT** в <a href={"{{model-plaza-url}}"}>model plaza</a>.

Не вставляйте Claude Code `{{anthropic-base-url}}` в Cursor OpenAI-compatible configuration.
