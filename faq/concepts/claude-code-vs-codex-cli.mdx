## 简短答案

Claude Code 和 Codex CLI 都是面向本地开发的 coding agent，但它们来自不同生态，配置方式和协议边界不同。

Claude Code 更贴近 Anthropic / Claude 生态，常见配置围绕 `ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN`、`CLAUDE.md`、permissions、hooks 和 MCP。

Codex CLI 更贴近 OpenAI / Codex 生态，常见配置围绕 `~/.codex/config.toml`、`model_provider`、`wire_api = "responses"`、`AGENTS.md`、sandbox 和 approval。

## 什么时候需要区分

- 你正在选择终端型 AI coding agent
- 你需要统一配置 Base URL、API Key 和模型
- 你想把项目规则写进长期生效的文件
- 你关心自动执行命令时的权限边界
- 你想让不同工具共用同一套模型 API 接入层

## 核心对比

| 维度 | Claude Code | Codex CLI |
| --- | --- | --- |
| 主要生态 | Anthropic / Claude | OpenAI / Codex |
| 常见模型协议 | Anthropic-compatible | OpenAI-compatible / Responses |
| 主要配置 | 环境变量、settings、permissions、hooks | `config.toml`、sandbox、approval、rules |
| 项目规则文件 | `CLAUDE.md` | `AGENTS.md` |
| 模型字段 | Claude 模型名、别名或 provider 映射 | `model`、`review_model`、provider id |
| 工具扩展 | MCP、hooks、permissions | MCP、plugins、rules、sandbox |

## 选择建议

如果你已经在 Claude 生态中工作，并且更关心 `CLAUDE.md`、Claude 模型、hooks 与 MCP，优先理解 Claude Code。

如果你更希望通过 `config.toml` 管理 provider、模型、review model、sandbox 和 approval，优先理解 Codex CLI。

如果团队同时使用两者，应把“工具前端”和“模型 API 层”分开看。工具决定如何读写代码、执行命令、审批风险；API 层决定请求发往哪个 provider、使用哪个模型、如何记录用量。

## 常见误区

- 以为 Claude Code 和 Codex CLI 只差模型名称。
- 把 `CLAUDE.md` 和 `AGENTS.md` 当成同一个文件。
- 把 Anthropic-compatible Base URL 填到 Codex CLI。
- 把 OpenAI-compatible `/v1` endpoint 填到 Claude Code 的 Anthropic 协议位置。
- 以为换 API provider 会改变工具自身的权限和沙箱策略。

## 关于 BetterToken

BetterToken 可以作为模型 API 接入层。Claude Code 场景通常使用 `{{anthropic-base-url}}`，Codex CLI 和其他 OpenAI-compatible 工具通常使用 `{{openai-base-url}}`。

它不替代 `CLAUDE.md`、`AGENTS.md`、permissions、hooks、sandbox 或 approval。这些仍由各自工具控制。
