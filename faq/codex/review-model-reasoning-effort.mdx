## Короткий ответ

`review_model` задаёт модель для `/review`; если поле не задано, Codex использует модель текущей сессии. `model_reasoning_effort` регулирует усилие рассуждения у моделей, которые поддерживают этот параметр через Responses API.

Большее усилие может помочь в сложной работе, но не гарантирует правильный ответ или меньшую общую стоимость. Это не настройка температуры или длины ответа.

## Связь полей

| Поле | Роль |
| --- | --- |
| `model` | Default model для обычной работы |
| `review_model` | Модель для review workflows, например `/review` |
| `model_reasoning_effort` | Reasoning strength для основной модели |
| `/model` | Вход для смены модели или reasoning в сессии |
| `/review` | Запуск review текущих изменений |

## Выбор усилия под задачу

Используйте эти значения как отправную точку и оценивайте результат по критериям приёмки:

| Задача | Начальная настройка | Что проверить |
| --- | --- | --- |
| Небольшая правка с чёткими границами или краткое объяснение | `low`, если поддерживается | Правильность и время ответа. |
| Обычная функция или ошибка с понятным воспроизведением | `medium`, если поддерживается | Тесты, полноту и лишние изменения. |
| Сложная диагностика, изменение нескольких модулей или подробное ревью | `high`; при необходимости попробуйте доступный уровень выше | Пропущенные ограничения, ложные замечания и полное время до пригодного результата. |

Доступные уровни зависят от модели, версии Codex и провайдера. Перед использованием `xhigh` или `max` проверьте варианты в `/model` и справочник выбранной модели. Поддержка уровня одной моделью не означает поддержку другой. Более высокое усилие может увеличить число токенов рассуждения и задержку; на итоговую стоимость также влияют повторы, размер контекста, вызовы инструментов и тарифы.

## Пример конфигурации

Задайте постоянные значения в `config.toml` внутри `CODEX_HOME` или в `~/.codex/config.toml`, если переменная не задана. Разместите эти ключи на верхнем уровне, перед таблицами TOML, и сохраните настройки провайдера и аутентификации:

```toml
model = "gpt-6-astra"
review_model = "gpt-6-astra"
model_reasoning_effort = "high"
```

## Файл конфигурации и настройки сессии

При запуске параметры CLI и переопределения `-c` имеют приоритет над настройками доверенного проекта, выбранного профиля и пользовательскими значениями. В текущих версиях Codex `--profile NAME` загружает `NAME.config.toml` из `CODEX_HOME`. Старые версии использовали другой формат профилей.

Чтобы изменить только усилие для одного запуска:

```bash
codex -c 'model_reasoning_effort="medium"'
```

В сессии используйте `/model` для выбора текущей модели и доступного уровня усилия. Правка файла не гарантирует немедленное изменение работающей сессии; проверяйте сохранённые значения в новой сессии. Режим Plan может использовать `plan_mode_reasoning_effort` или собственную предустановку, поэтому проверяйте его отдельно.

## Проверка действующих настроек

1. Выполните `codex --version`, затем откройте новую сессию из нужного каталога проекта.
2. В `/model` проверьте выбранное усилие, а в `/status` модель и параметры сессии. Если они отличаются от файла, проверьте параметры запуска, профиль, настройки проекта и `/debug-config`, если команда доступна.
3. Сравните одну типичную задачу на двух поддерживаемых уровнях в отдельных сессиях. Проверьте diff, тесты, время выполнения и записи использования BetterToken. Выберите настройку, которая обеспечивает нужное качество; меньшее усилие не гарантирует меньшую общую стоимость.

## Частые ошибки

- Думать, что `review_model` заменяет основную модель для всех задач.
- Считать reasoning effort параметром temperature.
- Использовать model ID, который не поддерживает текущий provider.
- Использовать максимальный reasoning effort для любой задачи.
- Смотреть только на model names, не проверяя фактический usage и quality.

## О BetterToken

Разные модели и reasoning settings влияют на расход. Usage records BetterToken помогают сравнивать input, output и cost на реальных задачах.

Копируйте model IDs у провайдера **GPT**, чтобы текущий provider мог их распознать.
