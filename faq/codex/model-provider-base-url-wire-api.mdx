## Короткий ответ

`model_provider` сообщает Codex CLI, какой provider использовать. Его значение должно совпадать с provider id, заданным в `[model_providers.<id>]`.

`base_url` — это API endpoint, куда отправляются model requests. Для OpenAI-compatible provider это обычно endpoint в формате `/v1`.

`wire_api` сообщает Codex, какую protocol shape использовать при общении с provider. В справочнике конфигурации Codex `responses` указан как поддерживаемое значение provider protocol.

## Когда это важно

- Вы настраиваете custom OpenAI-compatible provider
- Codex сообщает, что provider не найден, или model requests не проходят
- Вы не понимаете разницу между `model_provider` и `model`
- Вы добавляете BetterToken, OpenAI или другой provider в один `config.toml`
- Вам нужно разделить Base URL, API Key и Model ID

## Связь полей

| Поле | Назначение |
| --- | --- |
| `model_provider` | Выбирает активный provider id |
| `[model_providers.<id>]` | Определяет подробную конфигурацию одного provider |
| `name` | Отображаемое имя provider |
| `base_url` | Корневой API endpoint |
| `wire_api` | Provider protocol, часто `responses` |
| `model` | Default main model ID |
| `review_model` | Модель для code review flows, например `/review` |

## Рекомендуемый паттерн

Сохраняйте provider id одинаковым:

```toml
model_provider = "custom"
model = "gpt-5.5"

[model_providers.custom]
name = "BetterToken"
base_url = "{{openai-base-url}}"
env_key = "MODEL_PROVIDER_API_KEY"
wire_api = "responses"
requires_openai_auth = false
```

Это означает, что Codex использует provider `custom`, отправляет model requests на `{{openai-base-url}}` и общается через Responses API shape.

Не записывайте API Key напрямую в `config.toml`. Задайте его в терминале, из которого запускается Codex:

```bash
export MODEL_PROVIDER_API_KEY="YOUR_API_KEY"
```

В Windows PowerShell:

```powershell
$env:MODEL_PROVIDER_API_KEY="YOUR_API_KEY"
```

## Как проверить настройку

1. Убедитесь, что `model_provider = "custom"` точно совпадает с `[model_providers.custom]`.
2. Проверьте Base URL: `{{openai-base-url}}`, включая `/v1`.
3. Скопируйте актуальный Model ID у провайдера **GPT** в <a href={"{{model-plaza-url}}"}>model plaza</a>.
4. Полностью закройте Codex и запустите его из нового терминала, где задана переменная окружения.
5. Отправьте небольшую задачу на объяснение кода и дождитесь полного ответа.

## Частые ошибки

| Симптом | Причина | Решение |
| --- | --- | --- |
| Provider not found | Provider id не совпадает с названием таблицы | Используйте `custom` в обоих местах |
| При запуске нет API Key | Переменная из `env_key` недоступна | Задайте `MODEL_PROVIDER_API_KEY` и откройте новый терминал |
| `401` или `403` | Неверный API Key или смешана OpenAI-аутентификация | Скопируйте Key заново и задайте `requires_openai_auth = false` |
| `404` | В Base URL нет `/v1` или указан Anthropic endpoint | Используйте `{{openai-base-url}}` |
| Model not found | Указано display name, отключенная модель или Model ID другого provider | Скопируйте актуальный Model ID из model plaza |
| Ошибка Responses protocol | `wire_api` отсутствует или задан неверно | Укажите `wire_api = "responses"` |
