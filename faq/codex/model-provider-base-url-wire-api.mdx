## Короткий ответ

`model_provider` сообщает Codex CLI, какой provider использовать. Его значение должно совпадать с provider id, заданным в `[model_providers.<id>]`.

`base_url` — это API endpoint, куда отправляются model requests. Для OpenAI-compatible provider это обычно endpoint в формате `/v1`.

`wire_api` сообщает Codex, какую protocol shape использовать при общении с provider. В справочнике конфигурации Codex `responses` указан как поддерживаемое значение provider protocol.

## Когда это важно

- Вы настраиваете custom OpenAI-compatible provider
- Codex сообщает, что provider не найден, или model requests не проходят
- Вы не понимаете разницу между `model_provider` и `model`
- Вы добавляете BetterToken, OpenAI или другой provider в один `config.toml`
- Вам нужно разделить Base URL, API Key и Model ID

## Связь полей

| Поле | Назначение |
| --- | --- |
| `model_provider` | Выбирает активный provider id |
| `[model_providers.<id>]` | Определяет подробную конфигурацию одного provider |
| `name` | Отображаемое имя provider |
| `base_url` | Корневой API endpoint |
| `wire_api` | Provider protocol, часто `responses` |
| `model` | Default main model ID |
| `review_model` | Модель для code review flows, например `/review` |

## Найдите файлы и создайте резервные копии

Если задан свой `CODEX_HOME`, редактируйте `config.toml` и `auth.json` в этом каталоге. Иначе используйте `~/.codex` в macOS / Linux или `%USERPROFILE%\.codex` в Windows. CLI и App должны использовать один каталог. В WSL каталог пользователя отдельный.

Перед изменениями полностью закройте Codex. Сохраните резервные копии обоих файлов в защищённом месте. Создайте отсутствующие файлы. Заменяйте существующие настройки, не добавляйте повторные ключи или таблицы; сохраните остальные параметры.

<Warning>
  Эта настройка переключает вход через ChatGPT на авторизацию по API Key и не сохраняет доступ к официальному аккаунту. Защитите `auth.json` и резервные копии: не публикуйте их и не добавляйте в репозиторий.
</Warning>

## Рекомендуемый паттерн

### Измените config.toml

Разместите `model_provider`, `model` и `cli_auth_credentials_store` на верхнем уровне, перед всеми таблицами TOML, а не внутри профиля. ID выбранного провайдера должен совпадать с именем таблицы. Для файловой авторизации удалите `env_key` и `experimental_bearer_token` из настроек выбранного провайдера.

```toml
model_provider = "bettertoken"
model = "gpt-6-astra"
cli_auth_credentials_store = "file"

[model_providers.bettertoken]
name = "BetterToken"
base_url = "{{openai-base-url}}"
wire_api = "responses"
requires_openai_auth = true
request_max_retries = 4
stream_max_retries = 8
stream_idle_timeout_ms = 300000
supports_websockets = false
```

В примере используется GPT-6 Astra (`gpt-6-astra`). Для другой модели скопируйте полный ID из <a href={"{{model-plaza-url}}"}>model plaza</a> и замените `model`. GPT, Kimi и GLM используют одинаковую файловую авторизацию; автоматическая настройка доступна для GPT.

### Измените auth.json

Файл `auth.json` находится в том же каталоге, что и `config.toml`. Если файла `auth.json` нет, создайте его в этом каталоге. Запишите в него следующий JSON, замените `YOUR_API_KEY` на свой BetterToken API Key и сохраните файл.

```json
{
  "auth_mode": "apikey",
  "OPENAI_API_KEY": "YOUR_API_KEY"
}
```

## Перезапустите и проверьте

Сохраните оба файла. Запустите новый сеанс Codex CLI прямо из терминала:

```bash
codex
```

Полностью закройте Codex App, включая фоновые процессы, затем откройте его и создайте новую локальную задачу. Отправьте короткий запрос в каждом используемом клиенте. Нормальный ответ подтверждает подключение этого клиента.

## Устранение ошибок

При `401`, `403` или запросе входа проверьте активный каталог, Key в `auth.json`, `auth_mode = apikey`, `cli_auth_credentials_store = file` и `requires_openai_auth = true`. При ошибке провайдера или модели проверьте совпадение ID провайдера, `{{openai-base-url}}`, `wire_api = responses` и доступность модели. Если изменения не применились, проверьте переопределения конфигурации и убедитесь, что CLI и App используют один `CODEX_HOME`.
