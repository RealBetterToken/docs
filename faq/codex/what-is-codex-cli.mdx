## 简短答案

Codex CLI 是 OpenAI 的本地命令行 coding agent。它在你的终端中运行，可以读取工作区、编辑文件、执行命令，并按你的审批与沙箱设置完成开发任务。

它适合希望在本地仓库中用命令行方式处理代码修改、代码审查、测试修复、脚本编写和多步骤开发任务的用户。

Codex CLI 和普通 ChatGPT 对话不同。它不仅生成建议，还会围绕当前目录、项目说明、工具结果和本地执行权限来推进任务。

## 什么时候需要理解它

- 你正在第一次安装 `@openai/codex`
- 你不确定 Codex CLI、Codex App、Codex Web 的差别
- 你想在本地项目中使用 agent 修改文件
- 你需要配置自定义 API provider、Base URL 或模型
- 你想理解 sandbox、approval 和 `AGENTS.md` 的作用

## 核心概念

| 概念 | 说明 |
| --- | --- |
| Codex CLI | 本地终端中的 Codex coding agent |
| 工作区 | Codex 当前能读取、搜索和修改的目录 |
| `config.toml` | Codex CLI 的本地配置文件，用于设置模型、provider、sandbox 等 |
| `AGENTS.md` | 项目级说明文件，用来告诉 Codex 项目规则和协作约定 |
| Sandbox | 限制文件系统和网络访问的本地安全边界 |
| Approval | 决定哪些命令或操作需要用户确认 |

## 推荐工作流

1. 在要修改的项目目录中启动 Codex CLI。
2. 让它先阅读相关文件或说明，而不是直接要求它大范围改动。
3. 对复杂任务先要求计划，再允许它修改文件。
4. 根据任务风险选择合适的 sandbox 和 approval 模式。
5. 把长期项目约定写入 `AGENTS.md`，把一次性需求留在当前对话里。

如果你需要使用第三方 API provider，重点是 `config.toml` 中的 `model_provider`、`base_url`、`wire_api` 和模型字段。Codex / 外部工具通常使用 OpenAI-compatible endpoint；在本仓库中对应 `{{openai-base-url}}`。

## 常见误区

- 把 Codex CLI 当成只会回答问题的聊天工具。
- 以为 Codex CLI、Codex App、Codex Web 是完全相同的运行环境。
- 只改 `model`，不配置对应 provider 和 Base URL。
- 放开 sandbox 和 approval，却没有测试、代码审查或命令边界。
- 把 OpenAI-compatible Base URL 和 Anthropic-compatible Base URL 混用。

## BetterToken 在这里的位置

如果你使用自定义 OpenAI-compatible provider，BetterToken 可以作为 Codex CLI 的模型 API 层。它负责 API Key、Base URL、模型路由、余额和用量记录。

BetterToken 不替代 Codex CLI 的本地 sandbox、approval、`AGENTS.md` 或命令执行策略。
