## Короткий ответ

Codex CLI — это локальный coding agent в терминале. Он сфокусирован на локальных проектах, выполнении команд, изменении файлов и конфигурации через `config.toml`.

Codex App — это desktop application. Он лучше подходит для графического workflow, управления сессиями, plugins, Remote Control и функций приложения.

Codex Web / Cloud ближе к удаленному или browser-based agent workflow. Это не та же среда, что локальный CLI, и она не обязана разделять локальный доступ к файлам, sandbox, approval policy или config file.

## Когда нужно их различать

- Вы выбираете между CLI, App и Web
- Вы хотите сохранить официальный login state Codex App, но отправлять model calls через сторонний API
- Вы изменили локальный `config.toml`, но Web работает по-прежнему
- Вам нужно понять, где происходят file access, command execution и approvals
- Вы пишете командные правила использования Codex

## Ключевые различия

| Измерение | Codex CLI | Codex App | Codex Web / Cloud |
| --- | --- | --- | --- |
| Основной вход | Локальный терминал | Desktop app | Browser или remote environment |
| Главная настройка | `~/.codex/config.toml`, `AGENTS.md`, sandbox, approval | Login state, desktop features, provider switching | Cloud tasks, remote environments, repository authorization |
| Доступ к файлам | Local workspace | Зависит от текущего workspace и функций App | Зависит от remote environment и authorization |
| Лучше подходит для | Local development, быстрые команды, scripts, правки кода | Desktop sessions, plugins, Remote Control | Remote tasks и cloud development workflows |

## Как выбрать

Используйте Codex CLI, если основной workflow — локальное редактирование кода и выполнение команд в терминале.

Используйте Codex App, если вам важны desktop workflow, plugins или Remote Control. Если нужно сохранить официальный login state и использовать сторонний API, разделяйте authentication layer и model request layer.

Используйте Codex Web / Cloud, если задача должна выполняться в remote environment или browser-based task flow. Не считайте, что локальный `config.toml` управляет cloud runtime.

## Частые ошибки

- Думать, что изменения локального CLI `config.toml` автоматически влияют на Codex Web / Cloud.
- Смешивать официальный login Codex App и сторонний API Key.
- Считать, что у всех трех вариантов одинаковые filesystem permissions.
- Забывать, что sandbox и approval действуют в конкретной среде запуска.
- Смешивать plugins, Remote Control и model provider settings в один слой.

## О BetterToken

BetterToken относится к model request layer: какой API provider получает model calls. В Codex CLI обычная custom provider setup чаще всего хранится в `config.toml`. В сценариях Codex App с сохранением официального login state authentication и inference routing нужно настраивать отдельно.

BetterToken не меняет runtime boundary между CLI, App и Web / Cloud.
