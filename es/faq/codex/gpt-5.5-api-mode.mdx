Codex CLI y Codex App comparten `config.toml` y `auth.json` para las tareas locales. Esta configuración usa una BetterToken API Key mediante OpenAI Responses.

Actualiza Codex antes de usar `gpt-6-astra`.

## Localiza los archivos y crea copias de seguridad

Si has definido un `CODEX_HOME` personalizado, edita allí `config.toml` y `auth.json`. En caso contrario, usa `~/.codex` en macOS / Linux o `%USERPROFILE%\.codex` en Windows. CLI y App deben usar el mismo directorio. WSL tiene su propio directorio de usuario.

Cierra Codex por completo antes de editar. Guarda copias de ambos archivos en un lugar privado. Crea los archivos que falten. Sustituye los ajustes existentes sin duplicar claves ni tablas; conserva los demás ajustes.

<Warning>
  Esta configuración cambia el inicio de sesión con ChatGPT por la autenticación con API Key. No conserva el acceso a la cuenta oficial. Protege `auth.json` y sus copias; no los compartas ni los incluyas en el repositorio.
</Warning>

## Edita config.toml

Coloca `model_provider`, `model` y `cli_auth_credentials_store` en el nivel superior, antes de todas las tablas TOML, no dentro de un perfil. El ID del proveedor debe coincidir con el nombre de su tabla. Para esta autenticación por archivos, elimina `env_key` y `experimental_bearer_token` del proveedor seleccionado.

```toml
model_provider = "bettertoken"
model = "gpt-6-astra"
cli_auth_credentials_store = "file"

[model_providers.bettertoken]
name = "BetterToken"
base_url = "{{openai-base-url}}"
wire_api = "responses"
requires_openai_auth = true
request_max_retries = 4
stream_max_retries = 8
stream_idle_timeout_ms = 300000
supports_websockets = false
```

El ejemplo usa GPT-6 Astra (`gpt-6-astra`). Para otro modelo, copia su ID completo de la <a href={"{{model-plaza-url}}"}>model plaza</a> y sustituye `model`. GPT, Kimi y GLM usan la misma estructura de autenticación por archivos; la configuración automática está disponible para GPT.

## Edita auth.json

`auth.json` está en el mismo directorio que `config.toml`. Si no existe `auth.json`, créalo en ese directorio. Usa el siguiente JSON como contenido del archivo, reemplaza `YOUR_API_KEY` por tu BetterToken API Key y guarda el archivo.

```json
{
  "auth_mode": "apikey",
  "OPENAI_API_KEY": "YOUR_API_KEY"
}
```

## Reinicia y verifica

Guarda ambos archivos. Inicia una nueva sesión de Codex CLI directamente desde el terminal:

```bash
codex
```

Cierra Codex App por completo, incluidos los procesos en segundo plano. Ábrelo de nuevo y crea una tarea local nueva. Envía una indicación breve en cada cliente que uses. Una respuesta normal verifica la conexión de ese cliente.

## Solución de problemas

Ante `401`, `403` o una solicitud de inicio de sesión, revisa el directorio activo, la Key de `auth.json`, `auth_mode = apikey`, `cli_auth_credentials_store = file` y `requires_openai_auth = true`. Ante errores del proveedor o modelo, comprueba el ID del proveedor, `{{openai-base-url}}`, `wire_api = responses` y la disponibilidad del modelo. Si los cambios no se aplican, revisa las opciones que sobrescriben la configuración y confirma que CLI y App usan el mismo `CODEX_HOME`.
