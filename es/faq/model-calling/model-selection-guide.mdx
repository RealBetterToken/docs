## Cuándo necesitas esta información

- Alternas entre Claude Code, Codex CLI, Cursor, Cline u otras herramientas similares
- Un modelo funciona, pero es demasiado caro, lento o tiene poco contexto
- Quieres un modelo más económico para tareas por lotes
- Quieres conectar el mismo API gateway a varias herramientas de programación con IA

## Empieza por la herramienta y después elige el modelo

## Elegir según el tipo de tarea

| Tipo de tarea | Prioriza |
| --- | --- |
| Programación compleja, arquitectura y tareas largas | Calidad de razonamiento, ventana de contexto y estabilidad de las llamadas a herramientas |
| Preguntas diarias y generación ligera | Velocidad y coste |
| Traducción, clasificación y resúmenes por lotes | Precio unitario, rendimiento y estabilidad |
| Revisión de código y documentación técnica | Comprensión del código, contexto largo y salida estable |
| Tareas exploratorias | Empieza con un modelo de coste medio y cambia a uno más avanzado en los pasos críticos |

No envíes todas las tareas al modelo más caro de forma predeterminada. Muchas tareas por lotes no necesitan un razonamiento profundo ni mucha creatividad. Los modelos más rápidos y económicos suelen ser más adecuados.

## Flujo recomendado

1. Confirma si la herramienta admite una API compatible con OpenAI o con Anthropic.
2. Copia el Model ID vigente desde el <a href={"{{model-plaza-url}}"}>model plaza</a>.
3. Prueba la calidad, velocidad y coste con una tarea pequeña.
4. Revisa el uso en el panel antes de usar ese modelo a largo plazo.
5. Mantén un modelo alternativo más avanzado para tareas complejas en lugar de configurar uno solo.

## Errores comunes

- Fijarse solo en el nombre visible sin confirmar el Model ID.
- Suponer que el modelo más reciente siempre es el mejor para todas las tareas.
- Comparar solo la calidad de salida e ignorar la longitud de contexto, velocidad y coste.
- Mover tráfico de producción a un modelo nuevo sin hacer primero una prueba pequeña.
