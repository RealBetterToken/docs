## Respuesta breve

Cursor Rules indica a Cursor cómo trabajar en un proyecto. `AGENTS.md` es un archivo de instrucciones del repositorio que pueden leer muchos agentes de programación. `.cursorignore` controla qué archivos o directorios no debe indexar ni leer Cursor.

Los tres se relacionan con el contexto del proyecto, pero resuelven problemas distintos: Rules orienta el comportamiento, `AGENTS.md` proporciona instrucciones comunes para varios agentes y `.cursorignore` excluye contenido.

## Comparación

| Archivo o función | Función principal |
| --- | --- |
| Cursor Rules | Reglas de Cursor para el proyecto, el equipo o el usuario |
| `AGENTS.md` | Instrucciones del repositorio y normas de colaboración comunes para varios agentes |
| `.cursorignore` | Archivos o directorios que Cursor debe ignorar |
| API Key / Base URL | Configuración de las solicitudes al modelo, no reglas del proyecto |

## Contenido adecuado para Rules

- Estilo de programación del proyecto
- Convenciones del framework
- Reglas de componentes y directorios
- Requisitos de pruebas y validación
- Comportamiento de edición de Cursor

## Contenido adecuado para .cursorignore

- Artefactos de compilación grandes
- Directorios de dependencias
- Archivos generados
- Directorios sensibles que no deben indexarse
- Archivos grandes ajenos al desarrollo actual

## Errores habituales

- Escribir API Keys en Rules o `AGENTS.md`.
- Tratar `.cursorignore` como un sistema de seguridad completo.
- Mantener reglas obsoletas que confunden a la IA.
- Pensar que la configuración de la Base URL sustituye las reglas del proyecto.
- Mezclar Cursor Rules con `CLAUDE.md` de Claude Code.

## Acerca de BetterToken

BetterToken gestiona el acceso a la API del modelo y la visibilidad del uso. Cursor Rules, `AGENTS.md` y `.cursorignore` gestionan el contexto del proyecto y el comportamiento de edición.

El acceso a la API es solo el primer paso. La calidad de los resultados a largo plazo depende en gran medida de unas reglas claras y un contexto controlado.
