Codex CLI und Codex App verbinden sich über OpenAI Responses mit BetterToken. Die automatische Konfiguration verwendet die API-Key-Anmeldung von Codex. Bei der manuellen Konfiguration bleibt der Schlüssel in `BETTERTOKEN_API_KEY`.

## Wichtige Einstellungen

| Feld | Wert |
| --- | --- |
| API Key | Automatisch: API-Key-Anmeldung von Codex; manuell: `BETTERTOKEN_API_KEY` |
| Base URL | `{{openai-base-url}}` |
| Modell | `YOUR_MODEL_ID` |

## Voraussetzungen

- Installiere Node.js
- <a href={"{{register-url}}"}>Erstelle einen BetterToken API Key</a>
- Kopiere eine Modell-ID aus dem <a href={"{{model-plaza-url}}"}>model plaza</a> oder dem Dialog **Setup** des Key

## Installation

```bash
npm install -g @openai/codex
```

## Konfiguration über die Befehlszeile

Das automatische BetterToken-Konfigurationsskript schreibt die Anbieter-Konfiguration für Codex und speichert den BetterToken API Key in `~/.codex/auth.json`. Es setzt `requires_openai_auth = true`, damit Codex die API-Key-Anmeldung verwendet. Es benötigt Node.js und fragt nach API Key oder Modell-ID, wenn sie nicht als Argumente übergeben wurden.

<Warning>
  Die automatische Konfiguration wechselt von der offiziellen ChatGPT-Anmeldung zur API-Key-Anmeldung von Codex. Wenn du die offizielle Anmeldung behalten möchtest, überspringe das Skript und verwende die manuelle Anbieter-Konfiguration unten.
</Warning>

<Tabs>
  <Tab title="macOS / Linux">
    ```bash
    curl -fsSL "{{install-codex-provider-sh-url}}" | bash
    ```
  </Tab>
  <Tab title="Windows">
    ```powershell
    iwr "{{install-codex-provider-ps1-url}}" -OutFile "$env:TEMP\install-codex-provider.ps1"; powershell -ExecutionPolicy Bypass -File "$env:TEMP\install-codex-provider.ps1"
    ```
  </Tab>
</Tabs>

Öffne nach Abschluss `~/.codex/config.toml` (unter Windows `%USERPROFILE%\.codex\config.toml`). Prüfe, ob `model`, `review_model`, der BetterToken-Anbieter und `requires_openai_auth = true` korrekt eingetragen wurden. Führe dann die Neustartschritte unter **Verbindung prüfen** aus.

## Manuelle Konfiguration

GPT, Kimi und GLM verwenden dieselbe Struktur für `config.toml`. Ersetze nur `YOUR_MODEL_ID` durch eine aktuelle Modell-ID des ausgewählten Anbieters. Die Ein-Klick-Konfiguration über die Befehlszeile ist derzeit nur für GPT verfügbar.

### API Key festlegen

<Tabs>
  <Tab title="macOS / Linux">
    ```bash
    export BETTERTOKEN_API_KEY="YOUR_API_KEY"
    ```

    Füge diese Zeile zu `~/.zshrc` oder `~/.bashrc` hinzu, um die Variable dauerhaft zu speichern.
  </Tab>
  <Tab title="Windows PowerShell">
    ```powershell
    [Environment]::SetEnvironmentVariable("BETTERTOKEN_API_KEY", "YOUR_API_KEY", "User")
    $env:BETTERTOKEN_API_KEY = "YOUR_API_KEY"
    ```

    Der erste Befehl speichert die Variable für zukünftige Prozesse. Der zweite stellt sie in der aktuellen PowerShell-Sitzung bereit, bevor du Codex CLI startest.
  </Tab>
  <Tab title="Codex App">
    ```dotenv
    BETTERTOKEN_API_KEY="YOUR_API_KEY"
    ```

    Speichere diese Zeile in `~/.codex/.env` oder unter Windows in `%USERPROFILE%\.codex\.env`. Wenn du ein eigenes `CODEX_HOME` verwendest, speichere `.env` in diesem Verzeichnis. Beende Codex App nach der Änderung vollständig und öffne sie erneut.
  </Tab>
</Tabs>

<Warning>
  Trage den BetterToken API Key bei dieser manuellen Methode nicht in `~/.codex/auth.json` ein. Behalte dort die offizielle Anmeldung und lasse den eigenen Anbieter `BETTERTOKEN_API_KEY` über `env_key` lesen. Die automatische Methode oben ist ein separater API-Key-Anmeldemodus.
</Warning>

### config.toml konfigurieren

Bearbeite `~/.codex/config.toml`:

```toml
model_provider = "custom"
model = "YOUR_MODEL_ID"
review_model = "YOUR_MODEL_ID"
model_reasoning_effort = "high"

[model_providers.custom]
name = "BetterToken"
base_url = "{{openai-base-url}}"
env_key = "BETTERTOKEN_API_KEY"
wire_api = "responses"
requires_openai_auth = false
request_max_retries = 4
stream_max_retries = 8
stream_idle_timeout_ms = 300000
supports_websockets = false
```

`model_provider = "custom"` muss mit der Tabelle `[model_providers.custom]` übereinstimmen. Ersetze beide Werte für `YOUR_MODEL_ID` durch eine aktuelle vollständige Modell-ID.

## Verbindung prüfen

<Tabs>
  <Tab title="Codex CLI">
    Beende den aktuellen Codex-Prozess. Öffne ein neues Terminal und führe Folgendes aus:

    ```bash
    codex
    ```

    Sende eine kurze Aufgabe. Eine gestreamte Antwort ohne Anmeldeaufforderung, `401` oder Modellfehler bestätigt die Konfiguration.
  </Tab>
  <Tab title="Codex App">
    Beende Codex App vollständig, öffne sie erneut und erstelle eine neue Aufgabe. Sende eine kurze Aufgabe. Eine gestreamte Antwort ohne Anmeldeaufforderung, `401` oder Modellfehler bestätigt die Konfiguration.
  </Tab>
</Tabs>

## Modelle wechseln

Ändere `model` und optional `review_model`. Speichere die Datei, beende den aktuellen Codex-Prozess und starte ihn neu. Verwende die Modell-ID aus dem Setup-Dialog oder model plaza.

## Häufige Fehler

| Fehler | Lösung |
| --- | --- |
| `401` oder OpenAI-Anmeldeaufforderung | Automatisch: Prüfe, ob das Skript abgeschlossen wurde und `requires_openai_auth = true` gesetzt ist. Manuell: Prüfe `BETTERTOKEN_API_KEY`, `env_key` und `requires_openai_auth = false`. |
| Anbieter nicht gefunden | Stelle sicher, dass `model_provider = "custom"` mit `[model_providers.custom]` übereinstimmt. |
| Fehler im API-Modus | Behalte `wire_api = "responses"` bei und wechsle nicht zu Chat Completions. |
| Modell nicht gefunden | Ersetze `YOUR_MODEL_ID` durch eine aktuelle vollständige ID aus Setup oder dem model plaza. |
| Konfiguration nicht angewendet | Öffne für CLI ein neues Terminal. Beende Codex App vollständig, öffne sie erneut und erstelle eine neue Aufgabe. Prüfe bei manueller Konfiguration außerdem, ob der aktive Prozess `BETTERTOKEN_API_KEY` lesen kann. |

### Codex-Erweiterung

Die Codex-Erweiterung für VS Code verwendet dieselbe `config.toml`. Um die offizielle Anmeldung beizubehalten, ist jedoch eine andere Authentifizierungskonfiguration erforderlich. Siehe [Anleitung für die Codex-Erweiterung](/de/ai-tools/codex-vscode).

<Warning>
  Die Konfiguration für CLI/App und die Erweiterungskonfiguration mit offizieller Anmeldung sind Alternativen. Füge nicht zwei Tabellen `[model_providers.custom]` in dieselbe TOML-Datei ein.
</Warning>
