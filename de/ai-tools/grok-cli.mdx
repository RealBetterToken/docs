„Grok CLI“ kann zwei verschiedene Werkzeuge bezeichnen:

- **Grok Build** — der offizielle Coding Agent von xAI;
- **Community Grok CLI** — ein Open-Source-Projekt ohne Verbindung zu xAI.

Beide Clients wurden mit BetterToken verifiziert: Mit BetterToken API Key, Base URL und Model ID haben sie eine Modellantwort zurückgegeben. Diese Anleitung beginnt mit der einfacher konfigurierbaren **Community Grok CLI**.

<Warning>Beide Werkzeuge verwenden den Befehl `grok`. Sind beide installiert, startet die zuerst in `PATH` gefundene Version.</Warning>

## Grok CLI und Grok Build im Vergleich

| Merkmal | Offizieller Grok Build | Community Grok CLI |
| --- | --- | --- |
| Entwickler | xAI | `superagent-ai/grok-cli`, nicht mit xAI verbunden |
| Authentifizierung | Browser-Anmeldung oder `XAI_API_KEY` | `GROK_API_KEY` |
| Eigene Base URL | In `~/.grok/config.toml` | Mit `GROK_BASE_URL` |
| Modell | Alias in der Konfiguration | `GROK_MODEL` |
| Modelle über BetterToken aufrufen | Verifiziert | Verifiziert |
| Startbefehl | `grok` | `grok` |

Die Verifizierung gilt für Text- und Code-Modellanfragen, nicht für Tool-Aufrufe oder xAI-spezifische APIs.

## Community Grok CLI mit BetterToken verwenden

Die folgenden Befehle gelten für macOS, Linux und WSL. Native Windows wurde für den Community-Client nicht verifiziert.

### Installation

```bash
curl -fsSL https://raw.githubusercontent.com/superagent-ai/grok-cli/main/install.sh | bash
grok --version
```

Mit bereits installiertem Bun:

```bash
bun add -g grok-dev
```

### BetterToken konfigurieren

```bash
export GROK_BASE_URL="{{openai-base-url}}"
export GROK_API_KEY="YOUR_API_KEY"
export GROK_MODEL="YOUR_MODEL_ID"
```

Ersetze `YOUR_MODEL_ID` durch die vollständige Model ID aus der <a href={"{{model-plaza-url}}"}>model plaza</a> und verwende deinen <a href={"{{register-url}}"}>BetterToken API Key</a>.

### Verbindung prüfen

```bash
grok -p "Reply with only: OK"
```

Erst eine Modellantwort bestätigt, dass API Key, Base URL und Model ID funktionieren. Starte den Client nach Änderungen an Umgebungsvariablen neu.

## Offizieller Grok Build

[Grok Build](https://docs.x.ai/build/overview) ist der offizielle Terminal-Coding-Agent von xAI.

### Installation und Anmeldung

<Tabs>
  <Tab title="macOS / Linux / WSL">
    ```bash
    curl -fsSL https://x.ai/cli/install.sh | bash
    grok --version
    ```
  </Tab>
  <Tab title="Windows PowerShell">
    ```powershell
    irm https://x.ai/cli/install.ps1 | iex
    grok --version
    ```
  </Tab>
</Tabs>

Beim ersten Start öffnet Grok Build den Browser. Ohne Browser:

```bash
export XAI_API_KEY="YOUR_XAI_API_KEY"
grok
```

### BetterToken in Grok Build konfigurieren

```toml
[model.bettertoken]
model = "YOUR_MODEL_ID"
base_url = "{{openai-base-url}}"
name = "BetterToken"
env_key = "BETTERTOKEN_API_KEY"
api_backend = "chat_completions"

[models]
default = "bettertoken"
```

`BETTERTOKEN_API_KEY` ist ein frei gewählter Variablenname. Grok Build liest die in `env_key` angegebene Variable.

```bash
export BETTERTOKEN_API_KEY="YOUR_API_KEY"
grok inspect
grok -p "Reply with only: OK" -m bettertoken
```

<Note>Grok Build hat mit dieser Konfiguration eine Modellantwort über BetterToken zurückgegeben. Tool-Aufrufe und xAI-spezifische APIs wurden damit nicht verifiziert.</Note>

## Häufige Fehler

| Problem | Prüfung |
| --- | --- |
| Falscher Client startet | Pfad und Version aller `grok`-Befehle prüfen. |
| `401` oder `Unauthorized` | Community CLI liest `GROK_API_KEY`; Grok Build liest die Variable aus `env_key`. |
| `model not found` | Vollständige Model ID aus der model plaza kopieren und neu starten. |
| Anfrage geht weiter an xAI | `GROK_BASE_URL` prüfen oder in Grok Build `grok inspect` ausführen. |

## Modelle und Funktionsgrenzen

Verwende eine vollständige OpenAI-compatible Model ID aus der <a href={"{{model-plaza-url}}"}>model plaza</a>. X Search, Sprache, Bilder, Videos und andere xAI-spezifische APIs sind nicht Teil dieser BetterToken-Konfiguration.
