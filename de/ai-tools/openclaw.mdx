OpenClaw verbindet sich über `~/.openclaw/openclaw.json` mit BetterToken. Modelle des GPT-Anbieters verwenden `openai-responses`; andere unterstützte Anbieter verwenden `openai-completions`.

## Wichtige Einstellungen

| Feld | Wert |
| --- | --- |
| API Key | BetterToken API Key |
| Base URL | `{{openai-base-url}}` |
| Modell | `YOUR_MODEL_ID` |

## Voraussetzungen

- Installiere die aktuelle Version von OpenClaw
- <a href={"{{register-url}}"}>Erstelle einen BetterToken API Key</a>
- Kopiere eine Modell-ID aus dem <a href={"{{model-plaza-url}}"}>model plaza</a> oder dem Dialog **Setup** des Key

## Manuelle Konfiguration

### OpenClaw konfigurieren

Bearbeite `~/.openclaw/openclaw.json`. Verwende nur das Beispiel, das zum Anbieter deiner Modell-ID passt.

<Tabs>
  <Tab title="GPT: openai-responses">
    ```json
    {
      "models": {
        "mode": "merge",
        "providers": {
          "bettertoken": {
            "baseUrl": "{{openai-base-url}}",
            "apiKey": "YOUR_API_KEY",
            "api": "openai-responses",
            "models": [
              {
                "id": "YOUR_MODEL_ID",
                "name": "YOUR_MODEL_ID"
              }
            ]
          }
        }
      },
      "agents": {
        "defaults": {
          "model": {
            "primary": "bettertoken/YOUR_MODEL_ID"
          }
        }
      }
    }
    ```
  </Tab>
  <Tab title="Non-GPT: openai-completions">
    ```json
    {
      "models": {
        "mode": "merge",
        "providers": {
          "bettertoken": {
            "baseUrl": "{{openai-base-url}}",
            "apiKey": "YOUR_API_KEY",
            "api": "openai-completions",
            "models": [
              {
                "id": "YOUR_MODEL_ID",
                "name": "YOUR_MODEL_ID"
              }
            ]
          }
        }
      },
      "agents": {
        "defaults": {
          "model": {
            "primary": "bettertoken/YOUR_MODEL_ID"
          }
        }
      }
    }
    ```
  </Tab>
</Tabs>

Leite `api` nicht aus einem Modellnamen ab. GPT verwendet `openai-responses`. Verwende `openai-completions` für einen Nicht-GPT-Anbieter nur, wenn der model plaza oder der Setup-Dialog die Kompatibilität bestätigt.

## Verbindung prüfen

Führe Folgendes aus:

```bash
openclaw config validate
openclaw gateway restart
openclaw models list
openclaw models status
```

Die Konfiguration ist aktiv, wenn die Validierung erfolgreich ist, das Gateway neu startet und `bettertoken/YOUR_MODEL_ID` in Modellliste und Status erscheint. Wenn eine vorhandene Sitzung weiterhin ein altes Modell verwendet, starte eine neue Sitzung und prüfe erneut.

## Modelle wechseln

Füge das neue Modell zu `models.providers.bettertoken.models` hinzu und ändere `agents.defaults.model.primary` in `bettertoken/YOUR_MODEL_ID`. Speichere, validiere die Konfiguration und starte das Gateway neu.

## Häufige Fehler

| Fehler | Lösung |
| --- | --- |
| `config validate` schlägt fehl | Prüfe Kommas, Anführungszeichen und Klammern im JSON. |
| `401` | Kopiere `apiKey` erneut und entferne Leerzeichen. |
| `404` oder Protokollfehler | GPT muss `openai-responses` verwenden; Nicht-GPT muss `openai-completions` verwenden. Hänge keinen Endpunkt an die Base URL an. |
| Modell fehlt | Prüfe, ob es sowohl in der Modellliste des Anbieters als auch in `agents.defaults.model.primary` vorhanden ist. |
| Vorhandene Sitzung verwendet das alte Modell | Führe `openclaw gateway restart` aus und erstelle eine neue Sitzung. |

## Technische Details

<Accordion title="Responses und Chat Completions">
  Mit `openai-responses` ruft OpenClaw für Modelle des GPT-Anbieters `/v1/responses` auf. `openai-completions` ruft für bestätigte kompatible Nicht-GPT-Anbieter `/v1/chat/completions` auf. Beide verwenden `{{openai-base-url}}` als `baseUrl`.
</Accordion>
