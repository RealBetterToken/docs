Codex CLI ist der lokale Coding-Agent von OpenAI für die Kommandozeile. Er läuft in deinem Terminal, liest den ausgewählten Workspace, bearbeitet Dateien, führt Befehle aus und befolgt bei Entwicklungsaufgaben deine Sandbox- und Freigabeeinstellungen.

## Kurzantwort

Es ist nützlich, wenn du möchtest, dass ein Agent bei Codeänderungen, Code-Review, Testkorrekturen, Skripten und mehrstufiger Engineering-Arbeit in einem lokalen Repository hilft.

Codex CLI unterscheidet sich von einer normalen ChatGPT-Unterhaltung. Es schlägt nicht nur Code vor. Es arbeitet mit aktuellem Verzeichnis, Projektanweisungen, Tool-Ergebnissen und lokalen Ausführungsberechtigungen.

## Codex CLI, App und Web im Vergleich

| Option | Ausführungsort | Geeignet für |
| --- | --- | --- |
| Codex CLI | Lokales Terminal und Workspace | Befehle, Automatisierung und Repository-Arbeit |
| Codex App | Desktop-Anwendung | Visuelle Sitzungen, lokale Aufgaben und Kontofunktionen |
| Codex Web | Browser oder Cloud-Umgebung | Remote-Aufgaben ohne lokales Terminal |

Eine ausführliche Gegenüberstellung findest du unter [Codex CLI, Codex App und Codex Web](/de/faq/codex/codex-cli-vs-app-vs-web).

## Wann das wichtig ist

- Du installierst `@openai/codex` zum ersten Mal
- Du vergleichst Codex CLI, Codex App und Codex Web
- Du möchtest, dass ein Agent Dateien in einem lokalen Projekt bearbeitet
- Du musst einen eigenen API-Provider, eine Base URL oder ein Modell konfigurieren
- Du möchtest Sandbox, Freigabe und `AGENTS.md` verstehen

## Grundlegende Konzepte

| Konzept | Bedeutung |
| --- | --- |
| Codex CLI | Der Codex-Coding-Agent, der in deinem lokalen Terminal läuft |
| Workspace | Das Verzeichnis, das Codex lesen, durchsuchen und bearbeiten kann |
| `config.toml` | Die lokale Codex-Konfigurationsdatei für Modelle, Provider, Sandbox, Freigaben und anderes Verhalten |
| `AGENTS.md` | Eine Projekt-Anweisungsdatei, die Codex Repository-Regeln und Präferenzen für Zusammenarbeit mitteilt |
| Sandbox | Die lokale Sicherheitsgrenze für Dateisystem-, Netzwerk- und Befehlszugriff |
| Freigabe | Die Richtlinie, die entscheidet, welche Aktionen eine Bestätigung benötigen |

## Empfohlener Workflow

1. Starte Codex CLI im Projektverzeichnis, das du ändern möchtest.
2. Bitte es, relevante Dateien oder Anweisungen zu prüfen, bevor es umfassende Änderungen vornimmt.
3. Bitte bei komplexer Arbeit um einen Plan, bevor du Dateien ändern lässt.
4. Wähle Sandbox- und Freigabeeinstellungen anhand des Risikos der Aufgabe.
5. Lege dauerhafte Projektregeln in `AGENTS.md` und einmalige Anforderungen in der aktuellen Unterhaltung ab.

Wenn du einen Drittanbieter-API-Provider verwendest, konzentriere dich auf `model_provider`, `base_url`, `wire_api` und Modellfelder in `config.toml`. Codex und andere OpenAI-kompatible Tools verwenden normalerweise einen OpenAI-kompatiblen Endpunkt, der in dieser Dokumentation `{{openai-base-url}}` lautet.

## Häufige Fehler

- Codex CLI als reinen Chat-Assistenten behandeln.
- Annehmen, dass Codex CLI, Codex App und Codex Web in derselben Umgebung laufen.
- Nur `model` ändern, ohne den passenden Provider und die passende Base URL zu konfigurieren.
- Sandbox- und Freigabeeinstellungen ohne Tests, Review oder Befehlsgrenzen lockern.
- OpenAI-kompatible und Anthropic-kompatible Base URLs vermischen.

## Über BetterToken

Wenn du einen eigenen OpenAI-kompatiblen Provider verwendest, kann BetterToken als Modell-API-Schicht für Codex CLI dienen. Es verarbeitet API Key, Base URL, Modellrouting, Guthaben und Nutzungsaufzeichnungen.

BetterToken ersetzt weder die lokale Sandbox und Freigaben von Codex CLI noch `AGENTS.md` oder die Richtlinie zur Befehlsausführung.

Allgemeinen Zugang zur Codex API findest du auf der [Codex-API-Seite von BetterToken](https://bettertoken.ai/ru/codex-api/). Diese FAQ behandelt die Funktionsweise und lokale Konfiguration von Codex CLI.
