## Kurzantwort

`model_provider` teilt Codex CLI mit, welchen Provider es verwenden soll. Sein Wert muss mit einer unter `[model_providers.<id>]` definierten Provider-ID übereinstimmen.

`base_url` ist der API-Endpunkt, an den Modell-Requests gesendet werden. Für einen OpenAI-kompatiblen Provider verweist er normalerweise auf einen Endpunkt im `/v1`-Stil.

`wire_api` teilt Codex mit, welches Protokollformat bei der Kommunikation mit diesem Provider verwendet werden soll. In der Codex-Konfigurationsreferenz ist `responses` ein unterstützter Wert für das Provider-Protokoll.

## Wann das wichtig ist

- Du konfigurierst einen eigenen OpenAI-kompatiblen Provider
- Codex meldet, dass der Provider nicht gefunden wird, oder Modell-Requests schlagen fehl
- Du bist nicht sicher, worin sich `model_provider` von `model` unterscheidet
- Du setzt BetterToken, OpenAI oder einen anderen Provider in einer `config.toml` ein
- Du musst Base URL, API Key und Model ID voneinander trennen

## Beziehungen der Felder

| Feld | Zweck |
| --- | --- |
| `model_provider` | Wählt die aktive Provider-ID aus |
| `[model_providers.<id>]` | Definiert die detaillierte Konfiguration eines Providers |
| `name` | Anzeigename für den Provider |
| `base_url` | API-Stammendpunkt |
| `wire_api` | Provider-Protokoll, üblicherweise `responses` |
| `model` | Standard-Model-ID für das Hauptmodell |
| `review_model` | Modell für Code-Review-Abläufe wie `/review` |

## Dateien finden und sichern

Wenn du ein eigenes `CODEX_HOME` festgelegt hast, bearbeite dort `config.toml` und `auth.json`. Andernfalls nutze `~/.codex` unter macOS / Linux oder `%USERPROFILE%\.codex` unter Windows. CLI und App müssen dasselbe Verzeichnis nutzen. WSL hat ein eigenes Benutzerverzeichnis.

Beende Codex vor dem Bearbeiten vollständig. Sichere beide Dateien an einem privaten Ort. Lege fehlende Dateien an. Ersetze bestehende Einstellungen, ohne Schlüssel oder Tabellen zu duplizieren; behalte andere Einstellungen bei.

<Warning>
  Diese Konfiguration wechselt von der ChatGPT-Anmeldung zur API-Key-Authentifizierung. Sie erhält den Zugriff auf das offizielle Konto nicht. Schütze `auth.json` und seine Sicherungen; teile sie nicht und nimm sie nicht ins Repository auf.
</Warning>

## Empfohlenes Muster

### config.toml bearbeiten

Setze `model_provider`, `model` und `cli_auth_credentials_store` auf die oberste Ebene vor allen TOML-Tabellen, nicht in ein Profil. Die Provider-ID muss zum Tabellennamen passen. Entferne für diese Dateiauthentifizierung `env_key` und `experimental_bearer_token` aus dem gewählten Provider.

```toml
model_provider = "bettertoken"
model = "gpt-6-astra"
cli_auth_credentials_store = "file"

[model_providers.bettertoken]
name = "BetterToken"
base_url = "{{openai-base-url}}"
wire_api = "responses"
requires_openai_auth = true
request_max_retries = 4
stream_max_retries = 8
stream_idle_timeout_ms = 300000
supports_websockets = false
```

Das Beispiel nutzt GPT-6 Astra (`gpt-6-astra`). Kopiere für ein anderes Modell die vollständige ID aus der <a href={"{{model-plaza-url}}"}>model plaza</a> und ersetze `model`. GPT, Kimi und GLM nutzen dieselbe Dateiauthentifizierung; die automatische Einrichtung ist für GPT verfügbar.

### auth.json bearbeiten

`auth.json` befindet sich im selben Verzeichnis wie `config.toml`. Falls `auth.json` nicht existiert, erstelle die Datei in diesem Verzeichnis. Trage das folgende JSON als Dateiinhalt ein, ersetze `YOUR_API_KEY` durch deinen BetterToken API Key und speichere die Datei.

```json
{
  "auth_mode": "apikey",
  "OPENAI_API_KEY": "YOUR_API_KEY"
}
```

## Neu starten und prüfen

Speichere beide Dateien. Starte eine neue Codex-CLI-Sitzung direkt im Terminal:

```bash
codex
```

Beende Codex App einschließlich der Hintergrundprozesse vollständig. Öffne die App erneut und erstelle eine neue lokale Aufgabe. Sende in jedem verwendeten Client eine kurze Anfrage. Eine normale Antwort bestätigt die Verbindung dieses Clients.

## Fehlerbehebung

Prüfe bei `401`, `403` oder einer Anmeldeaufforderung das aktive Verzeichnis, den Key in `auth.json`, `auth_mode = apikey`, `cli_auth_credentials_store = file` und `requires_openai_auth = true`. Prüfe bei Provider- oder Modellfehlern die passende Provider-ID, `{{openai-base-url}}`, `wire_api = responses` und die Modellverfügbarkeit. Wenn Änderungen nicht greifen, prüfe Konfigurationsüberschreibungen und stelle sicher, dass CLI und App dasselbe `CODEX_HOME` nutzen.
