Для подключения Codex к BetterToken нужен custom model provider и API Key. `base_url` должен быть `{{openai-base-url}}`, протокол — `OpenAI Responses`.

<Info>
  Если вы хотите сохранить официальный login state Codex App, plugins или Remote Control при использовании стороннего API, используйте [настройку с сохранением login state](/ru/faq/codex/official-login-third-party-api).
</Info>

## Требования

- Установленный Node.js
- API Key BetterToken (<a href={"{{register-url}}"}>зарегистрироваться</a>)

<Warning>
  Перед настройкой очистите OpenAI-related переменные окружения, чтобы они не переопределили `config.toml`.

  Очистите:

  - `OPENAI_API_KEY`
  - `OPENAI_BASE_URL`

  macOS / Linux:

  ```bash
  unset OPENAI_API_KEY
  unset OPENAI_BASE_URL
  ```

  Windows PowerShell:

  ```powershell
  Remove-Item Env:OPENAI_API_KEY -ErrorAction SilentlyContinue
  Remove-Item Env:OPENAI_BASE_URL -ErrorAction SilentlyContinue
  [Environment]::SetEnvironmentVariable("OPENAI_API_KEY", $null, "User")
  [Environment]::SetEnvironmentVariable("OPENAI_BASE_URL", $null, "User")
  ```
</Warning>

## Установка Codex

```bash
npm install -g @openai/codex
```

## Настройка

<Tabs>
  <Tab title="Автоматическая настройка">
    Можно запустить автоматический скрипт BetterToken. Он записывает только provider-конфигурацию BetterToken и не заменяет предварительные требования выше. Скрипту нужен `Node.js`. Если API Key или модель не переданы явно, скрипт запросит их интерактивно, когда это поддерживается.

    Выберите шаг для своей ОС. Нужен только один вариант.

    <Steps>
      <Step title="macOS / Linux">
        ```bash
        curl -fsSL {{install-codex-provider-sh-url}} | bash
        ```
      </Step>
      <Step title="Windows">
        ```powershell
        iwr {{install-codex-provider-ps1-url}} -OutFile "$env:TEMP\install-codex-provider.ps1"; powershell -ExecutionPolicy Bypass -File "$env:TEMP\install-codex-provider.ps1"
        ```
      </Step>
    </Steps>
  </Tab>

  <Tab title="Настройка через CC Switch">
    Этот путь описан в [инструкции CC Switch](/ru/ai-tools/cc-switch#codex-cli).

    Перейдите сразу к [вкладке Codex в инструкции CC Switch](/ru/ai-tools/cc-switch#codex-cli).

    После настройки в CC Switch вернитесь на эту страницу, чтобы проверить запуск и остальные примечания.
  </Tab>

  <Tab title="Ручная настройка">
    <Steps>
      <Step title="Проверьте модели по умолчанию">
        Конфигурация ниже использует `gpt-5.5` как модель по умолчанию и `gpt-5.4` как review model. Если нужно выбрать другую модель, откройте <a href={"{{model-plaza-url}}"}>BetterToken model plaza</a> и скопируйте актуальный ID модели из группы **GPT**.
      </Step>

      <Step title="Проверьте расположение конфигов">
        Для ручной настройки нужен файл Codex `config.toml`.

        | Система | `config.toml` |
        | --- | --- |
        | macOS / Linux | `~/.codex/config.toml` |
        | Windows | `C:\Users\YOUR_USER\.codex\config.toml` |
      </Step>

      <Step title="Отредактируйте config.toml Codex">
        Откройте `config.toml`. Создайте его, если файла нет.

        <Warning>
          Этот блок применим только при ручном редактировании `~/.codex/config.toml`. Если вы настраиваете Codex через CC Switch, точно следуйте [инструкции CC Switch](/ru/ai-tools/cc-switch#codex-cli) и не заменяйте конфигурацию, которой управляет CC Switch.
        </Warning>

        Добавьте:

        ```toml
        model_provider = "{{codex-provider-id}}"
        model = "gpt-5.5"
        review_model = "gpt-5.4"
        model_reasoning_effort = "high"
        model_context_window = 1000000
        model_auto_compact_token_limit = 900000
        windows_wsl_setup_acknowledged = true

        [model_providers]
        [model_providers.{{codex-provider-id}}]
        name = "{{codex-provider-name}}"
        base_url = "{{openai-base-url}}"
        wire_api = "responses"
        requires_openai_auth = false
        request_max_retries = 4
        stream_max_retries = 8
        stream_idle_timeout_ms = 300000
        supports_websockets = false
        ```
      </Step>

      <Step title="Перезапустите Codex в терминале">
        После изменения `config.toml` остановите текущий процесс Codex и запустите его в новой terminal session.
      </Step>

      <Step title="Запустите Codex">
        ```bash
        codex
        ```
      </Step>
    </Steps>

    ### Справочник параметров

    В [официальном справочнике конфигурации Codex](https://developers.openai.com/codex/config-reference) указано, что `model_provider` ссылается на provider id внутри `model_providers`, custom provider задается через `[model_providers.<id>]`, а `wire_api = "responses"` — поддерживаемое значение provider protocol.

    | Конфигурация | Значение | Рекомендуемое значение |
    | --- | --- | --- |
    | `model_provider` | Выбирает model provider, который использует Codex. Значение должно совпадать с `[model_providers.{{codex-provider-id}}]`. | `"{{codex-provider-id}}"` |
    | `model` | Основная модель Codex для повседневного написания кода, правок и задач агента. | `"gpt-5.5"` |
    | `review_model` | Модель для команды `/review`. Если не задано, Codex использует текущую основную модель. | `"gpt-5.4"` |
    | `model_reasoning_effort` | Управляет reasoning strength для моделей с Responses API. Возможные значения: `minimal`, `low`, `medium`, `high`, `xhigh`. | `"high"` |
    | `model_context_window` | Сообщает Codex размер context window активной модели в токенах. | `1000000` |
    | `model_auto_compact_token_limit` | Автоматически сжимает историю диалога при достижении этого token threshold. | `900000` |
    | `windows_wsl_setup_acknowledged` | Флаг подтверждения Windows / WSL onboarding, чтобы избежать повторных setup prompts. | `true` |
    | `[model_providers]` | Родительская секция для custom model provider configuration. | `[model_providers]` |
    | `[model_providers.{{codex-provider-id}}]` | Определяет custom provider с id `{{codex-provider-id}}`; `model_provider = "{{codex-provider-id}}"` ссылается на эту секцию. | `[model_providers.{{codex-provider-id}}]` |
    | `name` | Отображаемое имя provider. Влияет только на отображение, не на request logic. | `"{{codex-provider-name}}"` |
    | `base_url` | Базовый API URL. Codex отправляет model requests на этот адрес. | `"{{openai-base-url}}"` |
    | `wire_api` | Provider protocol. В конфигурации Codex provider `responses` — поддерживаемое и default значение. | `"responses"` |
    | `requires_openai_auth` | Использовать ли официальную OpenAI authentication. Для этого custom proxy provider OpenAI auth отключен. | `false` |
    | `request_max_retries` | Максимальное число повторов для обычных failed HTTP requests. Официальное default значение — `4`. | `4` |
    | `stream_max_retries` | Максимальное число повторов при прерывании SSE stream. Официальное default значение — `5`; для proxy chain можно увеличить. | `8` |
    | `stream_idle_timeout_ms` | Idle timeout для SSE stream в миллисекундах. `300000` — это 5 минут. | `300000` |
    | `supports_websockets` | Объявляет ли provider поддержку Responses API WebSocket transport. | `false` |

    Примечание: [страница модели `gpt-5.5`](https://developers.openai.com/api/docs/models/gpt-5.5) показывает поддержку `high` reasoning effort и context window `1,050,000` tokens. Поэтому `model_context_window = 1000000` — разумное консервативное значение, а `model_auto_compact_token_limit = 900000` откладывает compaction и подходит для долгих задач.

    Если конфигурацию пишет CC Switch, предпочитайте сгенерированный им файл. Редактируйте эти значения вручную только для manual setup или troubleshooting.
  </Tab>
</Tabs>

## Проверка

После запуска отправьте тестовое сообщение. Обычный ответ означает, что подключение работает.

Если что-то не работает, проверьте:

1. `base_url` равен `{{openai-base-url}}`
2. `wire_api` остается `responses`
3. `model` — это ID модели из группы **GPT**
4. `model_provider` совпадает с provider id в `[model_providers.{{codex-provider-id}}]`
5. Старые переменные `OPENAI_API_KEY` или `OPENAI_BASE_URL` не мешают настройке
