OpenClaw 通过 `~/.openclaw/openclaw.json` 接入 BetterToken。GPT 提供商使用 `openai-responses`；其他支持的提供商使用 `openai-completions`。

## 重点信息

| 字段 | 填写内容 |
| --- | --- |
| API Key | BetterToken API Key |
| Base URL | `{{openai-base-url}}` |
| Model | `YOUR_MODEL_ID` |

## 准备工作

- 安装最新版 OpenClaw
- <a href={"{{register-url}}"}>创建 BetterToken API Key</a>
- 从<a href={"{{model-plaza-url}}"}>模型广场</a>或 Key 的 **Setup** 弹窗复制 Model ID

## 命令行配置

BetterToken Automatic setup 脚本会写入 OpenClaw 配置。脚本需要 Node.js；如果没有通过参数提供 API Key 或 Model ID，运行时会提示你输入。

<Tabs>
  <Tab title="macOS / Linux">
    ```bash
    curl -fsSL "{{install-openclaw-provider-sh-url}}" | bash
    ```
  </Tab>
  <Tab title="Windows">
    ```powershell
    iwr "{{install-openclaw-provider-ps1-url}}" -OutFile "$env:TEMP\install-openclaw-provider.ps1"; powershell -ExecutionPolicy Bypass -File "$env:TEMP\install-openclaw-provider.ps1"
    ```
  </Tab>
</Tabs>

运行后确认 `agents.defaults.model.primary` 使用 Setup 弹窗中的 `YOUR_MODEL_ID`，再执行下方的验证与 Gateway 重启命令。

## 手动配置

### 配置 OpenClaw

编辑 `~/.openclaw/openclaw.json`。只选择与你的 Model ID 所属提供商匹配的示例。

<Tabs>
  <Tab title="GPT：openai-responses">
    ```json
    {
      "models": {
        "mode": "merge",
        "providers": {
          "bettertoken": {
            "baseUrl": "{{openai-base-url}}",
            "apiKey": "YOUR_API_KEY",
            "api": "openai-responses",
            "models": [
              {
                "id": "YOUR_MODEL_ID",
                "name": "YOUR_MODEL_ID"
              }
            ]
          }
        }
      },
      "agents": {
        "defaults": {
          "model": {
            "primary": "bettertoken/YOUR_MODEL_ID"
          }
        }
      }
    }
    ```
  </Tab>
  <Tab title="非 GPT：openai-completions">
    ```json
    {
      "models": {
        "mode": "merge",
        "providers": {
          "bettertoken": {
            "baseUrl": "{{openai-base-url}}",
            "apiKey": "YOUR_API_KEY",
            "api": "openai-completions",
            "models": [
              {
                "id": "YOUR_MODEL_ID",
                "name": "YOUR_MODEL_ID"
              }
            ]
          }
        }
      },
      "agents": {
        "defaults": {
          "model": {
            "primary": "bettertoken/YOUR_MODEL_ID"
          }
        }
      }
    }
    ```
  </Tab>
</Tabs>

不要根据模型名称猜测 `api`。GPT 使用 `openai-responses`；非 GPT 提供商只有在模型广场或 Setup 弹窗确认支持后才使用 `openai-completions`。

## 验证连接

依次执行：

```bash
openclaw config validate
openclaw gateway restart
openclaw models list
openclaw models status
```

配置校验通过、Gateway 重启成功，并且 `bettertoken/YOUR_MODEL_ID` 出现在模型列表和状态中，即表示配置生效。已有会话仍显示旧模型时，新建会话后再次检查状态。

## 切换模型

把新模型加入 `models.providers.bettertoken.models`，再将 `agents.defaults.model.primary` 改为 `bettertoken/YOUR_MODEL_ID`。保存后重新执行校验与 Gateway 重启命令。

## 常见错误

| 错误 | 处理方式 |
| --- | --- |
| `config validate` 失败 | 检查 JSON 逗号、引号和括号。 |
| `401` | 重新复制 `apiKey`，确认没有空格。 |
| `404` 或协议错误 | GPT 检查 `openai-responses`；非 GPT 检查 `openai-completions`。Base URL 不要附加 endpoint。 |
| 模型未显示 | 检查模型是否同时存在于 provider 列表和 `agents.defaults.model.primary`。 |
| 旧会话仍用旧模型 | 执行 `openclaw gateway restart` 并新建会话。 |

## 技术说明

<Accordion title="Responses 与 Chat Completions">
  `openai-responses` 让 OpenClaw 请求 `/v1/responses`，用于 GPT 提供商。`openai-completions` 让 OpenClaw 请求 `/v1/chat/completions`，用于已确认支持的非 GPT 提供商。两者的 `baseUrl` 都填写 `{{openai-base-url}}`。
</Accordion>
