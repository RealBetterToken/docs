Codex CLI 和 Codex App 通过 OpenAI Responses 接入 BetterToken。配置文件是 `~/.codex/config.toml`，API Key 通过 `BETTERTOKEN_API_KEY` 环境变量提供。

## 重点信息

| 字段 | 填写内容 |
| --- | --- |
| API Key | 环境变量 `BETTERTOKEN_API_KEY` |
| Base URL | `{{openai-base-url}}` |
| Model | `YOUR_MODEL_ID` |

## 准备工作

- 安装 Node.js
- <a href={"{{register-url}}"}>创建 BetterToken API Key</a>
- 从<a href={"{{model-plaza-url}}"}>模型广场</a>或 Key 的 **Setup** 弹窗复制 Model ID

## 安装

```bash
npm install -g @openai/codex
```

## 命令行配置

BetterToken Automatic setup 脚本会写入 Codex provider 配置。脚本需要 Node.js；如果没有通过参数提供 API Key 或 Model ID，运行时会交互式提示输入。

<Tabs>
  <Tab title="macOS / Linux">
    ```bash
    curl -fsSL "{{install-codex-provider-sh-url}}" | bash
    ```
  </Tab>
  <Tab title="Windows">
    ```powershell
    iwr "{{install-codex-provider-ps1-url}}" -OutFile "$env:TEMP\install-codex-provider.ps1"; powershell -ExecutionPolicy Bypass -File "$env:TEMP\install-codex-provider.ps1"
    ```
  </Tab>
</Tabs>

运行后打开 `~/.codex/config.toml`（Windows 为 `%USERPROFILE%\.codex\config.toml`），确认 `model`、`review_model` 和 BetterToken provider 已正确写入，然后完全重启 Codex。

## 手动配置

GPT、Kimi 和 GLM 使用同一份 `config.toml` 结构，只需要把 `YOUR_MODEL_ID` 换成对应提供商的实际 Model ID。命令行一键配置目前仅用于 GPT。

### 设置 API Key

<Tabs>
  <Tab title="macOS / Linux">
    ```bash
    export BETTERTOKEN_API_KEY="YOUR_API_KEY"
    ```

    需要长期生效时，把这一行加入 `~/.zshrc` 或 `~/.bashrc`。
  </Tab>
  <Tab title="Windows PowerShell">
    ```powershell
    [Environment]::SetEnvironmentVariable("BETTERTOKEN_API_KEY", "YOUR_API_KEY", "User")
    $env:BETTERTOKEN_API_KEY = "YOUR_API_KEY"
    ```
  </Tab>
</Tabs>

<Warning>
  不要把 BetterToken API Key 写入 `~/.codex/auth.json`。该文件用于 Codex 官方登录；自定义 provider 应通过 `env_key` 读取环境变量。
</Warning>

### 配置 config.toml

编辑 `~/.codex/config.toml`：

```toml
model_provider = "custom"
model = "YOUR_MODEL_ID"
review_model = "YOUR_MODEL_ID"
model_reasoning_effort = "high"

[model_providers.custom]
name = "BetterToken"
base_url = "{{openai-base-url}}"
env_key = "BETTERTOKEN_API_KEY"
wire_api = "responses"
requires_openai_auth = false
request_max_retries = 4
stream_max_retries = 8
stream_idle_timeout_ms = 300000
supports_websockets = false
```

`model_provider = "custom"` 必须与 `[model_providers.custom]` 的 table 名一致。将两个 `YOUR_MODEL_ID` 替换为当前可用的完整 Model ID。

## 验证连接

打开新终端并运行：

```bash
codex
```

发送一条简短任务。能正常流式返回内容，且没有登录、`401` 或模型不存在错误，即表示配置成功。

## 切换模型

修改 `model` 和可选的 `review_model`，保存后结束当前 Codex 进程并重新启动。模型 ID 以 Setup 弹窗或模型广场为准。

## 常见错误

| 错误 | 处理方式 |
| --- | --- |
| `401` 或要求 OpenAI 登录 | 检查 `BETTERTOKEN_API_KEY`，并确认 `requires_openai_auth = false`。 |
| 找不到 provider | 确认 `model_provider = "custom"` 与 `[model_providers.custom]` 完全一致。 |
| API mode 错误 | 保留 `wire_api = "responses"`，不要改成 Chat Completions。 |
| 找不到模型 | 用 Setup 弹窗或模型广场中的完整 ID 替换 `YOUR_MODEL_ID`。 |
| 配置未生效 | 打开新终端，确认环境变量存在，并完全重启 Codex。 |

### Codex Extension

Codex VS Code Extension 与 CLI/App 共享 `config.toml`，但保留官方登录时使用不同鉴权配置。请查看 [Codex Extension 配置指南](/zh/ai-tools/codex-vscode)。

<Warning>
  CLI/App 配置与 Extension 保留官方登录配置是两个方案。不要把两个同名 `[model_providers.custom]` table 同时粘贴到一个 TOML 文件。
</Warning>
