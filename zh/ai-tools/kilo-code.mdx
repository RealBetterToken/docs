要在 Kilo Code 中使用 BetterToken，请准备 API Key，填写下表中的 Base URL，并从模型广场选择当前可用的 Model ID。

## 重点信息

| 字段 | 填写内容 |
| --- | --- |
| API Key | BetterToken API Key |
| Base URL | `{{openai-base-url}}` |
| Model | 从<a href={"{{model-plaza-url}}"}>模型广场</a>复制的当前 Model ID |

## 准备工作

- 已安装该工具的当前版本
- BetterToken API Key：<a href={"{{register-url}}"}>注册并获取</a>
- 从<a href={"{{model-plaza-url}}"}>模型广场</a>复制的 Model ID

### 工具特定要求

- 已安装 VS Code

## 安装

安装或打开 Kilo Code，然后继续完成下方手动配置。

## 手动配置

主要通过 Kilo Code 的设置界面完成以下配置，不需要手动编辑配置文件。

| 字段 | 填写内容 |
| --- | --- |
| API Key | BetterToken API Key |
| Base URL | `{{openai-base-url}}` |
| Model | 从<a href={"{{model-plaza-url}}"}>模型广场</a>复制的当前 Model ID |

### 配置步骤

<Steps>
  <Step title="清除冲突的环境变量">
    ```bash
    unset OPENAI_API_KEY
    unset OPENAI_BASE_URL
    ```
  </Step>

  <Step title="打开 Kilo Code 设置">
    打开 Kilo Code 的设置界面。
  </Step>

  <Step title="配置 API 提供商">
    按以下方式填写：

    - **API Provider** → `OpenAI Compatible`
    - **Base URL** → `{{openai-base-url}}`
    - **API Key** → 你的 BetterToken API Key
    - **Model** → 从<a href={"{{model-plaza-url}}"}>模型广场</a>复制的 **受支持提供商的模型 ID**
  </Step>

  <Step title="仅在官方文档明确要求时再配置额外 headers">
    我们查到的 Kilo Code 官方资料提到 OpenAI-compatible provider 支持可选自定义 headers，但没有把 `User-Agent` 列为 BetterToken 默认接入的必填项。

    如果你还接了自定义网关、租户路由或审计服务，再按对应上游服务的官方文档补充所需 headers。
  </Step>

  <Step title="重启 Kilo Code">
    修改配置后，请重启 VS Code 或重新加载 Kilo Code 插件，使新配置生效。
  </Step>
</Steps>

<Note>
  如需额外 headers，请以 Kilo Code 官方当前版本说明或上游网关要求为准，不要默认把 `User-Agent` 当作 BetterToken 必填项。
</Note>

## 验证连接

发送一条简短测试消息。工具正常返回内容，并且没有认证或 Model ID 错误，就说明连接成功。修改配置后请完全退出并重新启动工具。

## 切换模型

打开模型选择器，或修改配置中的 `Model` 字段。请填写<a href={"{{model-plaza-url}}"}>模型广场</a>中的完整 Model ID，然后重新启动当前会话。

## 常见错误

| 错误 | 排查方式 |
| --- | --- |
| `401` 或 `Unauthorized` | 检查 BetterToken API Key，并删除首尾空格。 |
| `404` | 检查 Base URL，不要附加具体 endpoint 路径。 |
| `model not found` | 从模型广场重新复制当前 Model ID。 |
| 配置未生效 | 保存配置，并完全退出后重新启动工具。 |
