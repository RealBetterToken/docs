Codex CLI 和 Codex App 的本地任务共用 `config.toml` 与 `auth.json`，通过 OpenAI Responses 使用 BetterToken API Key。

使用 `gpt-6-astra` 前先更新 Codex。

## 确认路径并备份

如果设置了自定义 `CODEX_HOME`，请编辑该目录中的 `config.toml` 和 `auth.json`。否则，macOS / Linux 使用 `~/.codex`，Windows 使用 `%USERPROFILE%\.codex`。CLI 与 App 必须使用同一目录。WSL 有独立的用户目录。

修改前完全退出 Codex，将两个文件备份到私密位置。文件不存在时可创建。替换已有设置，不要重复追加键或表；保留无关配置。

<Warning>
  此配置会从 ChatGPT 登录切换为 API Key 认证，不保留官方账号访问状态。妥善保护 `auth.json` 及其备份，不要提交到代码仓库或分享。
</Warning>

## 编辑 config.toml

将 `model_provider`、`model` 和 `cli_auth_credentials_store` 放在所有 TOML 表之前的顶层，不要放在 profile 中。选中的提供商 ID 必须与表名一致。使用本页文件认证时，移除该提供商下的 `env_key` 和 `experimental_bearer_token`。

```toml
model_provider = "bettertoken"
model = "gpt-6-astra"
cli_auth_credentials_store = "file"

[model_providers.bettertoken]
name = "BetterToken"
base_url = "{{openai-base-url}}"
wire_api = "responses"
requires_openai_auth = true
request_max_retries = 4
stream_max_retries = 8
stream_idle_timeout_ms = 300000
supports_websockets = false
```

示例使用 GPT-6 Astra（`gpt-6-astra`）。切换模型时，从<a href={"{{model-plaza-url}}"}>模型广场</a>复制完整 ID 并替换 `model`。GPT、Kimi 和 GLM 使用相同的文件认证结构；自动配置适用于 GPT。

## 编辑 auth.json

`auth.json` 与 `config.toml` 位于同一目录。如果找不到 `auth.json`，请在该目录中新建这个文件。将文件内容设为以下 JSON，把 `YOUR_API_KEY` 替换为你的 BetterToken API Key，然后保存。

```json
{
  "auth_mode": "apikey",
  "OPENAI_API_KEY": "YOUR_API_KEY"
}
```

## 重启并验证

保存两个文件后，在终端直接启动新的 Codex CLI 会话：

```bash
codex
```

完全退出 Codex App，包括后台进程，然后重新打开并新建本地任务。在实际使用的每个客户端发送简短提示词，确认能够正常返回。

## 故障排查

出现 `401`、`403` 或登录提示时，检查实际使用的目录、`auth.json` 中的 Key、`auth_mode = apikey`、`cli_auth_credentials_store = file` 和 `requires_openai_auth = true`。提供商或模型报错时，检查提供商 ID 是否一致、`{{openai-base-url}}`、`wire_api = responses` 及模型是否可用。配置未生效时，检查覆盖设置，并确认 CLI 与 App 使用相同的 `CODEX_HOME`。
