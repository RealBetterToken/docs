## 简短答案

`model_provider` 决定 Codex CLI 当前使用哪个 provider。它的值要对应下面 `[model_providers.<id>]` 中定义的 provider id。

`base_url` 是模型请求发往的 API 地址。对 OpenAI-compatible provider，它通常指向 `/v1` 风格的 endpoint。

`wire_api` 指定 Codex 与该 provider 通信时使用的协议形态。根据 Codex 配置参考，`responses` 是 provider 配置中支持的协议值之一。

## 什么时候需要理解它

- 你在配置自定义 OpenAI-compatible provider
- Codex 提示 provider 找不到或模型请求失败
- 你不确定 `model_provider` 和 `model` 的区别
- 你在把 BetterToken、OpenAI 或其他 provider 放进同一份 `config.toml`
- 你想区分 Base URL、API Key、Model ID 三个字段

## 字段关系

| 字段 | 作用 |
| --- | --- |
| `model_provider` | 选择当前使用哪个 provider id |
| `[model_providers.<id>]` | 定义某个 provider 的详细配置 |
| `name` | provider 的显示名称 |
| `base_url` | API 请求根地址 |
| `wire_api` | provider 通信协议，常见值是 `responses` |
| `model` | 默认主模型 ID |
| `review_model` | `/review` 等代码审查场景使用的模型 |

## 推荐配置方式

保持 provider id 一致：

```toml
model_provider = "custom"
model = "gpt-5.5"

[model_providers.custom]
name = "BetterToken"
base_url = "{{openai-base-url}}"
env_key = "MODEL_PROVIDER_API_KEY"
wire_api = "responses"
requires_openai_auth = false
```

这表示：Codex 使用名为 `custom` 的 provider，把模型请求发送到 `{{openai-base-url}}`，并按 Responses API 形态通信。

API Key 不应直接写进 `config.toml`。先在运行 Codex 的终端设置：

```bash
export MODEL_PROVIDER_API_KEY="YOUR_API_KEY"
```

Windows PowerShell 使用：

```powershell
$env:MODEL_PROVIDER_API_KEY="YOUR_API_KEY"
```

## 如何确认配置生效

1. 确认 `model_provider = "custom"` 与 `[model_providers.custom]` 完全一致。
2. 确认 Base URL 为 `{{openai-base-url}}`，其中包含 `/v1`。
3. 从<a href={"{{model-plaza-url}}"}>模型广场</a>复制 **GPT 分组**中当前可用的 Model ID。
4. 完全退出 Codex，在已设置环境变量的新终端中重新启动。
5. 发送一个小型代码解释任务，确认能收到完整响应。

## 常见错误与解决方法

| 现象 | 原因 | 处理方法 |
| --- | --- | --- |
| Provider 未找到 | provider id 与配置段名称不一致 | 两处都使用 `custom` |
| 启动时提示缺少 API Key | `env_key` 指向的环境变量不存在 | 设置 `MODEL_PROVIDER_API_KEY` 后重新打开终端 |
| `401` 或 `403` | API Key 无效或混用了 OpenAI 官方认证 | 重新复制 Key，并确认 `requires_openai_auth = false` |
| `404` | Base URL 缺少 `/v1` 或填入 Anthropic endpoint | 使用 `{{openai-base-url}}` |
| Model not found | 使用了展示名、下线模型或非 GPT 分组模型 | 从模型广场重新复制当前 Model ID |
| Responses 协议错误 | `wire_api` 缺失或值不正确 | 设置 `wire_api = "responses"` |
