## Resposta curta

O Codex CLI é o agente local de programação da OpenAI para linha de comando. Ele é executado no terminal, lê o workspace selecionado, edita arquivos, executa comandos e segue as configurações de sandbox e aprovação durante as tarefas de desenvolvimento.

Ele é útil quando você quer a ajuda de um agente para alterações de código, revisão, correções de testes, scripts e trabalhos de engenharia com várias etapas em um repositório local.

O Codex CLI é diferente de uma conversa comum no ChatGPT. Ele não apenas sugere código: trabalha com o diretório atual, as instruções do projeto, os resultados das ferramentas e as permissões locais de execução.

## Quando isso é importante

- Você está instalando `@openai/codex` pela primeira vez
- Você está comparando Codex CLI, Codex App e Codex Web
- Você quer que um agente edite arquivos em um projeto local
- Você precisa configurar um provedor de API, uma Base URL ou um modelo personalizado
- Você quer entender sandbox, aprovação e `AGENTS.md`

## Conceitos principais

| Conceito | Significado |
| --- | --- |
| Codex CLI | Agente de programação Codex executado no terminal local |
| Workspace | Diretório que o Codex pode ler, pesquisar e alterar |
| `config.toml` | Arquivo local de configuração do Codex para modelos, provedores, sandbox, aprovações e outros comportamentos |
| `AGENTS.md` | Arquivo de instruções do projeto que informa ao Codex as regras do repositório e as preferências de colaboração |
| Sandbox | Limite de segurança local para acesso ao sistema de arquivos, à rede e aos comandos |
| Aprovação | Política que define quais ações exigem confirmação |

## Fluxo recomendado

1. Inicie o Codex CLI no diretório do projeto que você deseja alterar.
2. Peça que ele examine os arquivos ou as instruções relevantes antes de fazer alterações amplas.
3. Em trabalhos complexos, peça um plano antes de permitir alterações nos arquivos.
4. Escolha as configurações de sandbox e aprovação conforme o risco da tarefa.
5. Coloque regras permanentes do projeto no `AGENTS.md` e requisitos pontuais na conversa atual.

Se você usa um provedor de API de terceiros, concentre-se em `model_provider`, `base_url`, `wire_api` e nos campos de modelo do `config.toml`. O Codex e outras ferramentas compatíveis com OpenAI geralmente usam um endpoint compatível com OpenAI, que nesta documentação é `{{openai-base-url}}`.

## Erros comuns

- Tratar o Codex CLI como um assistente apenas de chat.
- Achar que Codex CLI, Codex App e Codex Web são executados no mesmo ambiente.
- Alterar apenas `model` sem configurar o provedor e a Base URL correspondentes.
- Relaxar o sandbox e as aprovações sem testes, revisão ou limites de comandos.
- Misturar Base URLs compatíveis com OpenAI e com Anthropic.

## Sobre a BetterToken

Ao usar um provedor personalizado compatível com OpenAI, a BetterToken pode atuar como camada de API de modelos para o Codex CLI. Ela gerencia API Key, Base URL, roteamento de modelos, saldo e registros de uso.

A BetterToken não substitui o sandbox local, as aprovações, o `AGENTS.md` nem a política de execução de comandos do Codex CLI.
