## Resposta curta

As Cursor Rules indicam ao Cursor como trabalhar em um projeto. `AGENTS.md` é um arquivo de instruções do repositório que vários agentes de programação conseguem ler. `.cursorignore` controla quais arquivos ou diretórios o Cursor não deve indexar nem ler.

Todos estão relacionados ao contexto do projeto, mas resolvem problemas diferentes: as Rules orientam o comportamento, o `AGENTS.md` fornece instruções compartilhadas entre agentes e o `.cursorignore` exclui conteúdo.

## Comparação

| Arquivo / recurso | Função principal |
| --- | --- |
| Cursor Rules | Regras do Cursor no nível do projeto, da equipe ou do usuário |
| `AGENTS.md` | Instruções do repositório e normas de colaboração compartilhadas entre agentes |
| `.cursorignore` | Arquivos ou diretórios que o Cursor deve ignorar |
| API Key / Base URL | Configuração das solicitações de modelo, não regras do projeto |

## Conteúdo adequado para as Rules

- Estilo de programação do projeto
- Convenções do framework
- Regras de componentes e diretórios
- Requisitos de testes e validação
- Comportamento de edição do Cursor

## Conteúdo adequado para .cursorignore

- Artefatos de build grandes
- Diretórios de dependências
- Arquivos gerados
- Diretórios confidenciais que não devem ser indexados
- Arquivos grandes sem relação com o desenvolvimento atual

## Erros comuns

- Gravar API Keys nas Rules ou no `AGENTS.md`.
- Tratar o `.cursorignore` como um sistema completo de segurança.
- Manter regras desatualizadas que induzem a IA ao erro.
- Achar que a configuração da Base URL substitui as regras do projeto.
- Misturar as Cursor Rules com o `CLAUDE.md` do Claude Code.

## Sobre a BetterToken

A BetterToken gerencia o acesso à API de modelos e a visibilidade de uso. As Cursor Rules, o `AGENTS.md` e o `.cursorignore` controlam o contexto do projeto e o comportamento de edição.

O acesso à API é apenas a primeira etapa. A qualidade das respostas ao longo do tempo depende muito de regras claras e contexto controlado.
