`POST /v1/images/edits`

O endpoint de imagem para imagem usa um corpo de solicitação `multipart/form-data`. Envie uma ou mais imagens de referência e informe prompt e parâmetros como campos de formulário.

<Note>
  Use `{{openai-base-url}}` como `Base URL`. Envie sua BetterToken API Key por `Authorization: Bearer YOUR_API_KEY`.
</Note>

<Tip>
  Você pode preencher os campos e enviar imagens de referência no Playground à direita da página e enviar a solicitação diretamente para `{{images-edits-url}}`.
</Tip>

<Warning>
  Não use um corpo JSON comum em solicitações de imagem para imagem. Envie campos de texto e de arquivo com `multipart/form-data`.
</Warning>

## Valores recomendados

Envie estes campos explicitamente em todas as solicitações:

```text
model=gpt-image-2
n=1
response_format=b64_json
output_format=png
```

Use `image` para uma única referência. Para várias referências, repita os campos `image[]`.

## Uma imagem de referência

```bash
curl '{{images-edits-url}}' \
  -H 'Authorization: Bearer sk-***REDACTED***' \
  -F 'model=gpt-image-2' \
  -F 'prompt=Use this reference image to create a more polished square product hero image while keeping the main style consistent.' \
  -F 'n=1' \
  -F 'size=1024x1024' \
  -F 'response_format=b64_json' \
  -F 'output_format=png' \
  -F 'image=@reference.png'
```

## Várias imagens de referência

```bash
curl '{{images-edits-url}}' \
  -H 'Authorization: Bearer sk-***REDACTED***' \
  -F 'model=gpt-image-2' \
  -F 'prompt=Combine these reference images into one consistent promotional poster.' \
  -F 'n=1' \
  -F 'size=1024x1024' \
  -F 'response_format=b64_json' \
  -F 'output_format=png' \
  -F 'image[]=@reference-1.png' \
  -F 'image[]=@reference-2.jpg' \
  -F 'image[]=@reference-3.png'
```

## Edite uma área selecionada com máscara

Adicione o campo de arquivo opcional `mask` quando quiser direcionar a edição para uma área selecionada. O endpoint atual da BetterToken lê um único arquivo em `mask`. Não envie campos `mask[]` repetidos.

- A imagem original e a máscara devem ter o mesmo formato e as mesmas dimensões em pixels. Cada arquivo deve ter menos de 50 MB. Para máxima compatibilidade, use PNG com canal Alpha nos dois arquivos.
- A máscara deve conter um canal Alpha. Pixels totalmente transparentes (`Alpha 0`) marcam a área que o modelo pode redesenhar. Pixels totalmente opacos (`Alpha 255`) orientam o modelo a preservar essa área.
- Uma imagem RGB comum em preto e branco não é uma máscara válida se não tiver de fato um canal Alpha.
- Se você enviar vários campos `image[]`, a máscara será aplicada à primeira imagem de entrada.
- A máscara orienta o modelo. Ela não garante que os pixels fora da área transparente permaneçam absolutamente idênticos.

```bash
curl '{{images-edits-url}}' \
  -H 'Authorization: Bearer sk-***REDACTED***' \
  -F 'model=gpt-image-2' \
  -F 'prompt=Replace only the masked area with a blue circle. Preserve everything else.' \
  -F 'n=1' \
  -F 'size=1024x1024' \
  -F 'response_format=b64_json' \
  -F 'output_format=png' \
  -F 'image=@original.png' \
  -F 'mask=@mask.png'
```

### Edição com máscara em Python

Abra os dois arquivos em uma única instrução `with` para que o Python os feche após a solicitação:

```python
import requests

url = "{{images-edits-url}}"
headers = {"Authorization": "Bearer sk-***REDACTED***"}
data = {
    "model": "gpt-image-2",
    "prompt": "Replace only the masked area with a blue circle. Preserve everything else.",
    "n": "1",
    "size": "1024x1024",
    "response_format": "b64_json",
    "output_format": "png",
}

with open("original.png", "rb") as image_file, open("mask.png", "rb") as mask_file:
    files = {
        "image": ("original.png", image_file, "image/png"),
        "mask": ("mask.png", mask_file, "image/png"),
    }
    response = requests.post(url, headers=headers, data=data, files=files, timeout=300)

response.raise_for_status()
result = response.json()
```

### Verifique os arquivos antes do upload

Esta verificação mínima com Pillow valida os requisitos de formato, dimensões e canal Alpha. Para uma máscara local típica, ela também exibe um aviso se o canal Alpha não incluir áreas totalmente transparentes e opacas:

```python
from pathlib import Path
from PIL import Image

image_path = Path("original.png")
mask_path = Path("mask.png")

if image_path.stat().st_size >= 50 * 1024 * 1024 or mask_path.stat().st_size >= 50 * 1024 * 1024:
    raise ValueError("Each file must be smaller than 50 MB")

with Image.open(image_path) as image, Image.open(mask_path) as mask:
    if image.format != mask.format:
        raise ValueError("The image and mask formats must match")
    if image.size != mask.size:
        raise ValueError("The image and mask dimensions must match")
    if "A" not in mask.getbands():
        raise ValueError("The mask must contain an Alpha channel")
    alpha_min, alpha_max = mask.getchannel("A").getextrema()
    if alpha_min > 0 or alpha_max < 255:
        print("Warning: for a typical local mask, include fully transparent and fully opaque areas")
```

## Exemplo em Python

```python
import requests

url = "{{images-edits-url}}"
headers = {
    "Authorization": "Bearer sk-***REDACTED***",
}

data = {
    "model": "gpt-image-2",
    "prompt": "Use this reference image to create a more polished square product hero image while keeping the main style consistent.",
    "n": "1",
    "size": "1024x1024",
    "response_format": "b64_json",
    "output_format": "png",
}

with open("reference.png", "rb") as image_file:
    files = {
        "image": ("reference.png", image_file, "image/png"),
    }
    response = requests.post(url, headers=headers, data=data, files=files, timeout=300)

response.raise_for_status()
result = response.json()
b64_json = result["data"][0]["b64_json"]
```

## Tamanhos recomendados

| `size` | Proporção | Caso de uso |
| --- | --- | --- |
| `auto` | Automática | Seleção automática de tamanho |
| `1024x1024` | `1:1` | Imagens quadradas, avatares, capas e materiais |
| `1536x1024` | `3:2` | Pôsteres, banners e cenas horizontais |
| `1024x1536` | `2:3` | Capas e pôsteres verticais para celular |
| `1536x1152` | `4:3` | Imagens horizontais padrão, imagens de produto e gráficos de conteúdo |
| `1152x1536` | `3:4` | Imagens verticais padrão, capas de celular e pôsteres verticais |
| `2048x2048` | `1:1` | Imagens quadradas de alta resolução |
| `2048x1152` | `16:9` | Imagens horizontais de alta resolução |
| `3840x2160` | `16:9` | Imagens horizontais em 4K |
| `2160x3840` | `9:16` | Imagens verticais em 4K |

`size` representa a proporção esperada e a faixa de tamanho. Os pixels retornados podem ser mapeados ou ajustados pelo servidor. Use as dimensões da imagem decodificada em vez de cortar à força a saída para o valor solicitado.

## Salve a imagem

Uma resposta bem-sucedida segue o formato de resposta de imagem compatível com OpenAI:

```json
{
  "created": 1710000000,
  "data": [
    {
      "b64_json": "iVBORw0KGgoAAAANSUhEUgAA...(truncated)"
    }
  ]
}
```

Leia `data[0].b64_json` e salve-o como conteúdo de imagem base64. Sempre defina `output_format: "png"` para salvar a imagem decodificada como `.png`.

## Fluxo de resposta

Este endpoint é síncrono. Depois de enviar `POST /images/edits`, mantenha a solicitação HTTP aberta até o servidor responder. Quando a geração for concluída, o conteúdo da imagem será retornado em `data[0].b64_json`.

O endpoint não retorna `task_id`, nem há endpoint separado para consultar status ou baixar o resultado.
