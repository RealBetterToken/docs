“Grok CLI” pode indicar duas ferramentas diferentes:

- **Grok Build**, o coding agent oficial da xAI;
- **Grok CLI da comunidade**, um projeto open source sem vínculo com a xAI.

Os dois clientes foram verificados com a BetterToken: ambos retornaram uma resposta do modelo usando uma BetterToken API Key, Base URL e Model ID. Este guia começa pelo **Grok CLI da comunidade**, cuja configuração é mais direta.

<Warning>As duas ferramentas usam o comando `grok`. Se ambas estiverem instaladas, será executada a primeira versão encontrada no `PATH`.</Warning>

## Diferenças entre Grok CLI e Grok Build

| Item | Grok Build oficial | Grok CLI da comunidade |
| --- | --- | --- |
| Mantenedor | xAI | `superagent-ai/grok-cli`, sem vínculo com a xAI |
| Autenticação | Login pelo navegador ou `XAI_API_KEY` | `GROK_API_KEY` |
| Base URL personalizada | Em `~/.grok/config.toml` | Com `GROK_BASE_URL` |
| Modelo | Alias na configuração | `GROK_MODEL` |
| Chamar modelos pela BetterToken | Verificado | Verificado |
| Comando | `grok` | `grok` |

A verificação cobre solicitações de modelos de texto e código, não chamadas de ferramentas nem APIs exclusivas da xAI.

## Usar o Grok CLI da comunidade com a BetterToken

Os comandos abaixo servem para macOS, Linux e WSL. A configuração nativa no Windows não foi verificada para o cliente da comunidade.

### Instalação

```bash
curl -fsSL https://raw.githubusercontent.com/superagent-ai/grok-cli/main/install.sh | bash
grok --version
```

Se o Bun já estiver instalado:

```bash
bun add -g grok-dev
```

### Configurar a BetterToken

```bash
export GROK_BASE_URL="{{openai-base-url}}"
export GROK_API_KEY="YOUR_API_KEY"
export GROK_MODEL="YOUR_MODEL_ID"
```

Troque `YOUR_MODEL_ID` pelo Model ID completo da <a href={"{{model-plaza-url}}"}>model plaza</a> e use sua <a href={"{{register-url}}"}>BetterToken API Key</a>.

### Verificar a conexão

```bash
grok -p "Reply with only: OK"
```

Somente uma resposta do modelo confirma que API Key, Base URL e Model ID funcionam. Reinicie o cliente após alterar variáveis de ambiente.

## Grok Build oficial

[Grok Build](https://docs.x.ai/build/overview) é o coding agent oficial da xAI para terminal.

### Instalação e login

<Tabs>
  <Tab title="macOS / Linux / WSL">
    ```bash
    curl -fsSL https://x.ai/cli/install.sh | bash
    grok --version
    ```
  </Tab>
  <Tab title="Windows PowerShell">
    ```powershell
    irm https://x.ai/cli/install.ps1 | iex
    grok --version
    ```
  </Tab>
</Tabs>

Na primeira execução, o Grok Build abre o navegador. Sem navegador:

```bash
export XAI_API_KEY="YOUR_XAI_API_KEY"
grok
```

### Configurar a BetterToken no Grok Build

```toml
[model.bettertoken]
model = "YOUR_MODEL_ID"
base_url = "{{openai-base-url}}"
name = "BetterToken"
env_key = "BETTERTOKEN_API_KEY"
api_backend = "chat_completions"

[models]
default = "bettertoken"
```

`BETTERTOKEN_API_KEY` é um nome escolhido para o exemplo. O Grok Build lê a variável indicada em `env_key`.

```bash
export BETTERTOKEN_API_KEY="YOUR_API_KEY"
grok inspect
grok -p "Reply with only: OK" -m bettertoken
```

<Note>Com essa configuração, o Grok Build retornou uma resposta do modelo pela BetterToken. Chamadas de ferramentas e APIs exclusivas da xAI não foram verificadas.</Note>

## Erros comuns

| Problema | O que verificar |
| --- | --- |
| O cliente errado é iniciado | Confira o caminho e a versão de cada comando `grok`. |
| `401` ou `Unauthorized` | O cliente da comunidade lê `GROK_API_KEY`; o Grok Build lê a variável de `env_key`. |
| `model not found` | Copie o Model ID completo da model plaza e reinicie. |
| A solicitação ainda vai para a xAI | Verifique `GROK_BASE_URL` ou execute `grok inspect` no Grok Build. |

## Modelos e limites de recursos

Use um Model ID completo compatível com OpenAI da <a href={"{{model-plaza-url}}"}>model plaza</a>. X Search, voz, imagens, vídeo e outras APIs exclusivas da xAI não fazem parte desta configuração.
